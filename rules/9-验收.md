# 9 验收

本章落实设计理念的原则 15，并给出其他原则的核对方法。

## 9.1 自动检查

每次提交前在仓库根目录运行，四条都要通过。CI 运行同样的四条（`.github/workflows/check.yml`）。

| 命令 | 检查什么 |
|---|---|
| `node scripts/build.mjs --check` | aham.css 是最新生成的；tokens.json 的亮色和暗色键一一对应，没有重名变量 |
| `node scripts/lint.mjs` | 用到的 `--wb-*` 变量都有定义；src/ 里没有写死的颜色、字号、圆角和图标尺寸；文字不用主色；颜色对的对比度达标 |
| `node scripts/theme.mjs --check` | 三值生成的默认主题和样例主题达到对比度要求，默认主题和手调值相差不超过 ΔE 3 |
| `node --test` | 计算函数、筛选语义、单据规则和文件结构 |

## 9.2 无障碍

| 项 | 要求 |
|---|---|
| 文字对比度 | 正文、次要文字、辅助说明、占位文字和空值至少 4.5:1。`--wb-faint` 只用于图标和禁用文字，至少 3:1，见 2.1。表见 [2-视觉.md](2-视觉.md) 2.3 |
| 图形对比度 | 焦点框、状态圆点、分类色图标、输入框和按钮的描边至少 3:1 |
| 颜色以外的提示 | 状态有文字，错误有文字说明，分类有名称 |
| 焦点 | 每个能操作的元素都有可见焦点框；弹层关闭后焦点回到原处 |
| 键盘 | 全部操作能用键盘完成，见 [7-键盘与命令.md](7-键盘与命令.md) |
| 可访问名 | 只有图标的按钮有 `aria-label`；输入框有关联的标签（`aria-labelledby` 或包在 label 里） |
| 播报 | 轻提示、AI 结果、上传结果用 `role="status"`；字段错误用 `role="alert"` |
| 增强对比度 | 系统开启时分隔线也达到 3:1，次要文字加深，焦点框 3px |
| 减少动态效果 | 系统开启时去掉过渡 |
| 最小字号 | 12px |
| 点击区域 | 电脑上至少 32px，触屏上至少 44px |

## 9.3 每个页面要看的情况

| 情况 | 要求 |
|---|---|
| 长内容 | 长名称换行或省略加悬停全文，不撑破布局；长数字不溢出列 |
| 空值 | 按 [10-数据格式.md](10-数据格式.md) 10.5 写；必填项空着时用错误色 |
| 输入错误 | 原值保留、写明原因和改法、阻止保存、能定位到字段 |
| 只读 | 系统生成的值和不允许修改的状态下，没有可编辑的样子 |
| 保存失败 | 不说保存成功，改动保留，能再试 |
| 空结果 | 写原因，给出口 |
| 无权限 | 写缺什么权限 |
| 加载、网络异常 | 1 秒内不显示；首次加载用同尺寸灰块 `.wb-skeleton`；失败写原因和重试（失败状态没有参考实现） |
| 并发修改 | 见 [5-单据.md](5-单据.md) 5.7（没有参考实现） |

## 9.4 截图核对

改视觉的提交要截图核对：

- 页面：列表、工作清单、单据（显示态、编辑态带错误、审批中、已生效）、记录详情、打印预览、设置、控件总览、对外填报页。
- 宽度：1280、1440、1920px；再看一次 1024px 和 390px。对外填报页以 390px 为主要宽度。
- 主题：亮色、暗色各一次。
- 打印：打印预览页输出 PDF，确认一页 A4、没有空白页、表头重复。

截图核对要人看过才算通过。规则里写的对比度是按公式算的，没有在真机屏幕上逐一目测。

和参考对象对比时（例如 Linear 的截图），先把两张图换算到同一比例再并排看。换算方法：用截图里尺寸已知的元素定比例，例如 macOS 窗口按钮直径 12pt。不同比例的截图并排看，会把字号差 20% 以上误判成设计差异（[docs/research/Linear字体字号-调研.md](../docs/research/Linear字体字号-调研.md) 4.1）。

## 9.5 交付前自查

给 AI 和人用同一张表：

1. 颜色、字号、间距、圆角都来自变量，没有写死的值。
2. 一个页面只有一个主按钮；每个按钮只用文字或只用图标。
3. 状态用圆点加文字；颜色用在 [2-视觉.md](2-视觉.md) 2.2 允许的地方；灰底只用在一行高的元素上。
4. 表单标签在上，必填星号只在编辑态出现；日期、金额、空值按 [10-数据格式.md](10-数据格式.md) 写。
5. 单据的每个状态只露出这个状态能用的操作。
6. 删除、作废、撤回之前有确认弹窗，按钮写动作。
7. 消息用对了元素（[6-反馈.md](6-反馈.md) 6.1）。
8. 新的快捷键已登记，提示和实际按键一致。
9. 四条自动检查通过。
10. 截图核对过亮色和暗色。
11. 每个元素答得出谁在什么时候用；有流程的页面开头写清在等谁（[设计理念.md](../设计理念.md) 原则 2、3）。
12. 改视觉的，按 9.7 的风格判据逐条核对。

## 9.6 方案确认流程

界面的新设计和改版按下面的顺序做。前五条在写代码之前完成。

1. **先做方案。** 改界面先做一个能点的方案，在亮色、暗色和 390px 宽下自己测过。用户确认方案后再改代码。
2. **附取舍表。** 每份方案附一张取舍表，逐个元素写出谁在什么时候用、判断和做法（保留、删除、合并）。
3. **重要页面出 3 个版本。** 用户选定后可以组合各版的做法。
4. **先调研同类软件。** 设计一类页面之前，先看市场上成熟的同类软件怎么做，写明出处和看过的版本或日期。
5. **逐页打磨。** 除了用户指出的问题，设计者自己逐页检查用词、间距、空状态和操作反馈。
6. **分阶段审计。** 每个阶段结束时，从多个维度审计一次：信息结构、视觉、文案、对外体验和代码，不限于界面。审计结果逐条列出原文、问题和改法。

取舍表的表头固定为五列。下面以报价单页为例：

| 元素 | 谁在什么时候用 | 不看会不会做错 | 别处能不能看到 | 决定 |
|---|---|---|---|---|
| 下一步提示条 | 销售打开报价单时，确认现在等谁 | 会：不知道该催谁 | 不能 | 保留 |
| 关键信息里的价税合计 | 销售和审批人打开时先核对金额 | 会：金额错了要退回 | 汇总栏也有，但滚动后才看到 | 保留，滚动后收起 |
| 变更记录 | 出了争议时查谁改过 | 不会：日常不看 | 不能 | 折叠在页尾一行 |
| 单据头的「复制」按钮 | 条件变了，复制一张新报价 | 不会：一周用几次 | 「更多」菜单里有 | 删去，只留在菜单里 |

## 9.7 风格判据

改视觉的提交按下表逐条核对，每条写「通过」或写出不通过的位置。判据来自 [设计理念.md](../设计理念.md) 第 4 节。示例页按 1440×900、亮色截图核对，第 12 条另看暗色和三种宽度。

| 编号 | 判据 | 原则 | 核对方法 |
|---|---|---|---|
| S1 | 单行列表一屏至少 14 行 | 7 | 数截图里完整显示的数据行 |
| S2 | 工作台页面一屏只出现 13px 和 12px 两档字号，20px 标题和 24px 金额汇总除外 | 7 | 在浏览器里统计屏幕内文字的计算字号 |
| S3 | 主色蓝只出现在主按钮、焦点框、当前项标记、进行中的阶段图标 | 8 | 截图里找出全部蓝色像素所在的元素 |
| S4 | 正文链接用正文色加下划线 | 8 | 查看正文和评论里的链接 |
| S5 | 图标 14px，列表行里最多一个阶段图标或状态图标 | 9 | 量取图标尺寸，数每行的图标 |
| S6 | 侧栏比内容区深一档，当前项用 `--wb-nav-selected` 底色，不用主色 | 1 | 取色 |
| S7 | 内容区没有带边框或底色的卡片，一行高的元素除外 | 6 | 查看截图 |
| S8 | 列表行不折行，同一项的右边缘对齐 | 6、7 | 在截图上画竖线核对 |
| S9 | 没有渐变、发光和静止元素的阴影 | 1、8 | 查看截图和样式 |
| S10 | 详情页正文最宽 640px 居中，属性栏 288px | 4 | 量取 |
| S11 | 页面上的每个操作都能用键盘完成，并能在命令面板里搜到 | 11 | 只用键盘走一遍主要流程 |
| S12 | 亮色、暗色，1440px、1024px、390px 宽都没有横向滚动、遮挡和截断的文字 | 1 | 截图核对 |
