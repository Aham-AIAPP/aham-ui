# 1 总则

本章落实设计理念的原则 2、13、16，并列出每条原则落实在哪一章。

版本 10.0.0。本目录十一个文件是 Aham UI 的全部规则。规则背后的总体标准和原则写在仓库根目录的 [设计理念.md](../设计理念.md)，先读那一篇。取值以 [tokens.json](../tokens.json) 为准，样式以生成的 [aham.css](../aham.css) 为准，行为以 [aham.js](../aham.js) 为准。规则和这三个文件不一致时，按缺陷处理，改到一致。

## 1.1 适用范围

Aham UI 覆盖两种界面：在电脑浏览器里使用的业务管理系统，例如 CRM、ERP、MES 的列表、单据、详情和设置页；以及这类系统发给公司外部人员填写的对外填报页。

| 范围 | 状态 |
|---|---|
| 电脑浏览器，1280–1920px 宽 | 主要设计宽度，所有示例按这个范围验收 |
| 平板和手机浏览器 | 能用：导航收起、表单单列、触屏行高 44px；不单独设计 |
| 对外填报页，电脑和手机浏览器 | 按 [4-页面.md](4-页面.md) 4.12 设计，390px 宽必须验收 |
| 官网、营销页、阅读页 | 不覆盖 |
| macOS 应用、Office 文档、HTML 邮件 | 不在本规则范围，需要时另立项 |

## 1.2 设计原则

原则的含义、原因和判据见 [设计理念.md](../设计理念.md) 第 4 节，冲突时的取舍次序见第 5 节。下表列出每条原则主要由哪几章的规则落实。

| 原则 | 主要落实在 |
|---|---|
| 1 内容在前，界面退后 | 2.1 中性色、4.1 外框 |
| 2 元素按用途留 | 1.2、4.3、4.8，验收见 9.5 |
| 3 页面开头写清现在等谁 | 3.13 下一步提示条 |
| 4 同一个对象一页到底 | 4.8 记录详情页 |
| 5 记录类信息靠后 | 4.8 记录详情页 |
| 6 结构靠间距和对齐，少用线和框 | 2.6 间距、2.8 线条、4.3 列表行、11.1 表面层级 |
| 7 信息密，但不压人 | 2.5 字号、2.7 尺寸、4.3 列表行 |
| 8 颜色克制，只表达含义 | 2.2 颜色、2.12 主题生成 |
| 9 图标少而小 | 2.9 图标、3.15 阶段图标 |
| 10 操作的位置可预期 | 3.2 按钮、4.8 来路、第 5 章单据、第 7 章 |
| 11 工具不挡路 | 第 7 章 |
| 12 每次操作都有回应，动效只说明来去 | 第 11 章 |
| 13 一个概念一个词 | 1.4 术语、6.6 文案 |
| 14 AI 的结果标明依据，人确认后生效 | 第 8 章 |
| 15 好的改动不被察觉 | 9.4 截图核对、9.7 风格判据 |
| 16 按用户的问题组织页面，不按数据结构 | 4.8 记录详情页、6.6 文案、9.6 方案确认流程、9.8 挤压测试 |

几条常用的取值：工作台正文 14px，一屏只用 14px 和 12px 两档字号；列表单行 44px；明细表和数据表格行高 36px，紧凑 32px；控件 32px；图标 14px；侧栏 220px，收起 52px。

## 1.3 视觉来源

| 来源 | 借鉴内容 | 依据的可靠程度 |
|---|---|---|
| Linear | 整体风格：文字侧栏、无表头的分组单行列表、正文加右侧属性栏、颜色和图标的克制程度、字号层级、G 加字母跳转、命令面板、快捷键、右键菜单、列表键盘、筛选 | Linear 没有公开成套的设计规范。依据是官方博客、帮助文档和一张项目页截图的实测，见 [docs/research/Linear字体字号-调研.md](../docs/research/Linear字体字号-调研.md)。截图实测的数值误差约 ±1px |
| Claude 客户端 | 中性色和表面层级、细线、圆角、浮层阴影 | Anthropic 没有公开客户端的界面规范。中性色取自客户端截图量取，并和第三方仓库 Caho1/open-claude-ui 的取值核对过，两边不一致时以截图为准 |
| SAP Fiori | 页型、对象页的显示态和编辑态、草稿、消息分级、语义色、选择控件选型、按钮位置 | 公开规范，来源链接见 [docs/research/](../docs/research/) 的规划草案 |

- 中性色、细线和浮层阴影按 Claude 客户端的量取值使用，取值和来源见 [2-视觉.md](2-视觉.md) 2.1。
- 主色、状态色、分类色、字体文件和图标由 Aham 自定，不取自任何一家。
- Linear 的品牌色（靛蓝）、默认深色、官网的渐变和发光不借鉴。

## 1.4 术语

同一个概念全文只用一个词。

| 词 | 含义 | 不用的说法 |
|---|---|---|
| 单据 | 有编号、有状态、要提交或审批的业务对象，如报价单、订单、合同 | 表单、对象 |
| 记录 | 没有审批流程的业务对象，如客户、联系人 | 条目 |
| 显示态 / 编辑态 | 同一张单据只读和可改的两种状态，版式相同 | 查看模式、编辑模式 |
| 主按钮 | 一个页面上最主要的那个操作，蓝底白字，一页一个 | 强调按钮、CTA |
| 轻提示 | 屏幕右下角几秒后消失的确认消息（toast） | 提示条、吐司 |
| 提示条 | 单据头下方、说明整张单据状态或阻断原因的一条横幅（strip） | 横幅、通知栏 |
| 确认弹窗 | 不可撤销的操作之前问一次的模态窗口 | 对话框、确认框 |
| 消息框 | 确认弹窗、错误、警示、信息这类只有一两个按钮的模态窗口的统称（message box） | 对话框、警告框 |
| 页脚工具栏 | 编辑态和新建态贴在单据页底部、放取消和保存的一条工具栏（footer toolbar） | 底部栏、操作栏 |
| 关键信息 | 单据头和记录详情页标题下只读的几对「标签 + 值」（header facets） | 头部卡片、概要 |
| 工作记录 | 对象本身的往来记录，如跟进、电话、拜访、处理记录，按时间排成一条线，是正文的一部分 | 动态（动态指系统记下的修改和事件） |
| 用语表 | 产品自己的业务词表：用哪个词、什么意思、不用的说法 | 术语库、词典 |
| 草稿 | 编辑中自动保存、只有本人看得到、没有生效的版本 | 暂存、临时稿 |
| 视图 | 保存下来的一组筛选、排序、分组和列（variant） | 方案、变式 |
| 字段状态 | 单个字段上的错误或提醒（value state） | 校验提示 |
| 消息列表 | 编辑态里收集全部字段错误和提醒的弹层 | 错误汇总 |
| 分类色 | 区分类别用的 6 个颜色 | 彩色、辅助色 |
| 下一步提示条 | 标题下方写「等谁、做什么、计划日期」的一行（`.wb-next`） | 待办条、行动条 |
| 阶段条 | 横向画出多阶段流程、每段写状态的一行（`.wb-stages`） | 进度条、流程图 |
| 阶段图标 | 列表行里用一个 14px 圆形图标表示对象所在的阶段（`.wb-stage-icon`） | 状态图标、进度环 |
| 侧栏 | 页面左侧的文字导航，宽 220px，可以收起成 52px 的图标栏（`.wb-rail`） | 导航栏、菜单 |
| 汇总栏 | 单据页右侧 240px 的一栏，放金额汇总、收款计划和审批进度（`.wb-context`） | 侧栏、右栏 |
| 对外填报页 | 发给公司外部的人填写、不显示导航的页面（`.wb-form-page`） | 外链页、H5 页 |
| 编辑 | 按钮文字：改已有的内容 | 修改、更改 |
| 新建 | 按钮文字：创建一个对象 | 创建、新增 |
| 添加 | 按钮文字：在表格或列表里加一行，或把已有对象加进来 | 增加、新增 |
| 加入 | 把已有对象放进另一个对象，例如把记录加入项目 | 归入、挂到 |

## 1.5 文件分工

| 文件 | 内容 | 谁改 |
|---|---|---|
| tokens.json | 全部取值：颜色、字号、间距、尺寸、断点 | 改取值只改这里 |
| src/*.css | 样式源文件，按主题分文件 | 改样式改这里 |
| aham.css | 由 `node scripts/build.mjs` 生成，页面只引这一个 | 不手改 |
| aham.js | 行为脚本，ES 模块，无依赖 | 改行为改这里 |
| components/*.json | 每个控件和组合的结构、类名、状态、键盘 | 和 src、aham.js 一起改 |
| rules/*.md | 规则正文 | 规则变了先改这里 |
| examples/ | 示例页，用来核对规则 | 规则改了要同步 |

类名前缀 `wb-`，根节点 `.aham-workbench`，CSS 变量 `--wb-`。tokens.json 的键名就是变量名：键 `row` 生成 `--wb-row`。

## 1.6 规则的写法

- 每条规则写到能核对：写数值、写条件、写例外的判断标准。
- 规则之间冲突时，编号大的文件服从编号小的文件，同一文件里具体的服从笼统的。不写「本条优先于某条」的例外。
- 有参考实现的规则，写出函数名或类名；没有参考实现的，写明「没有参考实现」，不写版本号：规则只写当前版本，版本号见本章开头。
- 每章开头写明本章落实设计理念的哪几条原则。
