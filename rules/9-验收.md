# 9 验收

## 9.1 自动检查

每次提交前在仓库根目录运行，三条都要通过。CI 运行同样的三条（`.github/workflows/check.yml`）。

| 命令 | 检查什么 |
|---|---|
| `node scripts/build.mjs --check` | aham.css 是最新生成的；tokens.json 的亮色和暗色键一一对应，没有重名变量 |
| `node scripts/lint.mjs` | 用到的 `--wb-*` 变量都有定义；src/ 里没有写死的颜色、字号、圆角；颜色对的对比度达标 |
| `node --test` | 计算函数、筛选语义、单据规则和文件结构 |

## 9.2 无障碍

| 项 | 要求 |
|---|---|
| 文字对比度 | 正文和次要文字至少 4.5:1；占位文字和空值至少 2.5:1（只用在不承载信息的地方）。表见 [2-视觉.md](2-视觉.md) 2.3 |
| 图形对比度 | 焦点框、状态圆点、分类色图标至少 3:1 |
| 颜色以外的提示 | 状态有文字，错误有文字说明，分类有名称 |
| 焦点 | 每个能操作的元素都有可见焦点框；弹层关闭后焦点回到原处 |
| 键盘 | 全部操作能用键盘完成，见 [7-键盘与命令.md](7-键盘与命令.md) |
| 可访问名 | 只有图标的按钮有 `aria-label`；输入框有关联的标签（`aria-labelledby` 或包在 label 里） |
| 播报 | 轻提示、AI 结果、上传结果用 `role="status"`；字段错误用 `role="alert"` |
| 增强对比度 | 系统开启时控件边框达到 3:1，焦点框 3px |
| 减少动态效果 | 系统开启时去掉过渡 |
| 最小字号 | 12px |
| 点击区域 | 电脑上至少 32px，触屏上至少 44px |

## 9.3 每个页面要看的情况

| 情况 | 要求 |
|---|---|
| 长内容 | 长名称换行或省略加悬停全文，不撑破布局；长数字不溢出列 |
| 空值 | 必填写「没填」，选填写「–」 |
| 输入错误 | 原值保留、写明原因和改法、阻止保存、能定位到字段 |
| 只读 | 系统生成的值和不允许修改的状态下，没有可编辑的样子 |
| 保存失败 | 不说保存成功，改动保留，能再试 |
| 空结果 | 写原因，给出口 |
| 无权限 | 写缺什么权限 |
| 加载、网络异常 | 同尺寸灰块；失败写原因和重试（8.0 没有参考实现） |
| 并发修改 | 见 [5-单据.md](5-单据.md) 5.6（8.0 没有参考实现） |

## 9.4 截图核对

改视觉的提交要截图核对：

- 页面：列表、单据（显示态、编辑态带错误、审批中、已生效）、打印预览、设置、控件总览。
- 宽度：1280、1440、1920px；再看一次 1024px 和 390px。
- 主题：亮色、暗色各一次。
- 打印：打印预览页输出 PDF，确认一页 A4、没有空白页、表头重复。

截图核对要人看过才算通过。规则里写的对比度是按公式算的，没有在真机屏幕上逐一目测。

## 9.5 交付前自查

给 AI 和人用同一张表：

1. 颜色、字号、间距、圆角都来自变量，没有写死的值。
2. 一个页面只有一个主按钮。
3. 状态用圆点加文字；颜色用在 [2-视觉.md](2-视觉.md) 2.2 允许的地方。
4. 表单标签在上，必填星号只在编辑态出现。
5. 单据的每个状态只露出这个状态能用的操作。
6. 删除、作废、撤回之前有确认弹窗，按钮写动作。
7. 消息用对了元素（[6-反馈.md](6-反馈.md) 6.1）。
8. 新的快捷键已登记，提示和实际按键一致。
9. 三条自动检查通过。
10. 截图核对过亮色和暗色。
