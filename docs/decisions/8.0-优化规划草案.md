## 2 Claude 客户端视觉风格

### 2.1 资料情况

- 【未查到】Anthropic 没有公开 Claude 客户端的界面设计规范。
- 【查到】Anthropic 在 GitHub 公开了一份给 AI 生成文档用的品牌规范：主色 Dark `#141413`、Light `#faf9f5`、Mid Gray `#b0aea5`、Light Gray `#e8e6dc`；强调色 Orange `#d97757`、Blue `#6a9bcc`、Green `#788c5d`；标题字体 Poppins，正文字体 Lora。来源：[anthropics/skills · brand-guidelines](https://github.com/anthropics/skills/blob/main/skills/brand-guidelines/SKILL.md)。这份规范用于生成 PPT、文档，客户端界面的字体与它不同【推测】。
- 【第三方】[webdesignhot 的 Claude.ai 规格](https://www.webdesignhot.com/api/design-md/claude-ai.md) 写的是：主色 clay `#cd6f47`，正文 `#121212`，细线用 `rgba(18,18,18,0.06 / 0.12 / 0.18)` 三档，字体 Anthropic Sans / Anthropic Serif / Anthropic Mono，圆角 4、6、8、12、16。这份数据针对营销网站，取值方法未说明。
- 【第三方】[rar.design 的文章](https://rar.design/posts/claude-interface-design-philosophy) 写的主色是 `#da7756`，字体提到 Styrene B 和 Tiempos，并说品牌由 Geist 设计公司完成。两份第三方资料的色值互相不一致。

### 2.2 可借鉴的特征

| 编号 | 特征 | 依据 | 对应到 Aham 的做法 |
|---|---|---|---|
| C1 | 底色是偏暖的米白，分隔色也带一点暖调 | 品牌色【查到】；客户端里的用法【观察】 | Aham 现在是冷灰 `#F3F3F3` / `#E7E7E7`，「冷色的纸」写进了品牌身份（DESIGN §1.1）。要不要改，见第 5 节问题 1。 |
| C2 | 强调色只出现在很少几处，如标志和发送按钮 | 【观察】 | Aham 规则已经是「蓝只做点缀」。差距在执行：7.5 单据页每个小节标题前都有蓝竖条（B2）。 |
| C3 | 分隔线细、对比低，用半透明黑色 | 【第三方】 | Aham 用实色 `#E7E7E7`。改成半透明黑后，同一条线放在白底和灰底上深浅一致【推测】。 |
| C4 | 对话正文用衬线体，界面文字用无衬线体 | 【第三方】+【观察】 | Aham 禁用衬线。管理软件以表格和数字为主，我建议界面继续只用无衬线；长文和 AI 输出可以讨论。见问题 3。 |
| C5 | 图标细线、单色、尺寸小 | 【观察】 | Aham 用 Lucide，默认描边 2px（24px 网格），16px 时约 1.33px。可把默认描边改成 1.5，仓库已有 `.icon--thin` 类。 |
| C6 | 层次靠留白、字号和字重，容器少 | 【观察】 | DESIGN §0 已写「留白是首要分隔」。7.5 单据页的卡片套小节块违背这一条（A5、B2）。 |
| C7 | 静置无阴影，只有浮层有阴影 | 【第三方】+【观察】 | Aham 已一致，不用改。 |

我的判断【推测】：Aham 的原则文字和 Claude 客户端的方向基本相同。「互联网化」的感觉主要来自三处执行偏差：44px 行高、单据页的多层装饰、大圆角和胶囊。底色冷暖是品牌选择，单独讨论。

如果需要更准的依据，可以提供几张 Claude 客户端截图（亮色、暗色、设置页、对话页各一张），我按截图量取间距、线色和字号，替换上表的【观察】。

## 3 SAP Fiori 规范要点

### 3.1 内容密度

【查到】[Content Density](https://www.sap.com/design-system/fiori-design-web/v1-136/foundations/visual/cozy-compact)：

- 触控设备用 cozy，触控区域 44px；鼠标键盘设备用 compact，行和工具栏 32px。
- compact 档字号不变，只缩小间距和控件。
- 同一页面和同一层级不混用两档，密度在应用级设置。

### 3.2 页型选择

【查到】[List Report](https://www.sap.com/design-system/fiori-design-web/v1-84/page-types/floorplans/list-report-floorplan-sap-fiori-element/usage)、[Object Page](https://www.sap.com/design-system/fiori-design-web/v1-71/page-types/floorplans/object-page/usage)：

| 页型 | 用途 |
|---|---|
| List Report（列表报表） | 在大量单据里查找并处理，需要筛选栏 |
| Worklist（工作清单） | 逐条处理少量待办 |
| Object Page（对象页） | 查看、新建、修改一张单据的全部内容 |
| Initial Page（初始页） | 用户已知单号或扫码，直接定位一张单据 |
| Wizard（向导） | 新建步骤多、用户不熟悉流程 |
| 新建弹窗 | 必填字段少于 8 个时可以用弹窗新建 |

### 3.3 录入与修改

【查到】Object Page 和 [Object Handling](https://www.sap.com/design-system/fiori-design-web/v1-108/foundations/best-practices/global-patterns/object-handling/manage-objects)：

- 显示态和编辑态版式相同，切换时内容不移动位置。
- 整页编辑用于单页对象；只有少数分区可改时，只把这些分区设为编辑态，或用弹窗修改。
- 进入编辑的按钮叫「编辑」，完成按钮叫「保存」；新建时两个按钮都叫「创建」，复制时触发按钮叫「复制」、完成按钮叫「创建」。
- 新建时标题先写「新建 + 对象名」，有了名称或编号再替换。

### 3.4 草稿与锁定

【查到】[Draft Handling](https://www.sap.com/design-system/fiori-design-web/v1-148/foundations/best-practices/global-patterns/object-handling/draft-handling)：

- 开始新建或修改时，后台建一份草稿，每 20 秒自动保存一次。自动保存不生效，要点「保存」才生效。
- 修改中的单据，别人看到的仍是已保存版本，草稿只有本人可见。
- 离开有草稿的页面时，弹窗给三个选项：保存、保留草稿、放弃草稿。
- 放弃草稿要确认；没有改动时直接删除草稿，不问。
- 一个人修改时别人不能进入编辑；30 分钟无操作后锁失效，别人可以接手，原草稿作废。
- 列表可按编辑状态筛选：全部、我的草稿、他人锁定、他人未保存的修改、未修改。

### 3.5 操作位置与主按钮

【查到】[Action Placement](https://www.sap.com/design-system/fiori-design-web/v1-148/foundations/best-practices/global-patterns/action-placement)：

- 页眉工具栏放整张单据的操作，如编辑、删除、复制、分享，右对齐。
- 页脚工具栏放完成类操作，如保存、提交、过账、批准、驳回，以及取消。顺序是前进操作、备选操作、取消。
- 表格工具栏放这张表的操作，如添加行、删除选中行。
- 整页只有一个主按钮，页眉和页脚合计。
- 行内的标准操作（查看、编辑、删除）用图标放在行右侧；自定义行操作最多一个。
- 列表页里，依赖勾选的操作在没勾选时禁用；行内操作不能用时隐藏，不禁用。

### 3.6 必填与校验

【查到】[Label](https://www.sap.com/design-system/fiori-design-web/v1-151/ui-elements/label/usage)、[Form Field Validation](https://www.sap.com/design-system/fiori-design-web/v1-139/ui-elements/form-field-validation/usage)：

- 必填字段在标签后加星号，只在编辑态显示。
- 推荐标签放在输入框上方。
- 值改过且焦点离开时，只校验这一项。
- 点「创建」或「保存」时校验整张表单；这一步必须有，不能只靠失焦校验。
- 出错的字段显示错误状态和说明；页脚的消息按钮显示条数，点开是按字段列出的消息列表。
- 只读字段不显示校验状态。
- 保存的前提是所有必填项已填、数据一致（Draft Handling 页）。

### 3.7 消息分级

【查到】[Message Handling](https://www.sap.com/design-system/fiori-design-web/v1-84/foundations/best-practices/global-patterns/messaging/messaging)：

| 元素 | 用途 |
|---|---|
| 提示条（Message Toast） | 成功消息，几秒后自动消失 |
| 消息框（Message Box） | 和字段无关的消息，或需要用户做决定，必须确认 |
| 消息条（Message Strip） | 页面内的一般说明或对象状态 |
| 消息列表（Message Popover） | 收集表单和表格字段的错误、警告 |
| 字段状态（Value State） | 单个字段的错误、警告 |
| 空页（Message Page） | 没有数据、筛选无结果 |

严重程度四级：错误（必须解决才能继续）、警告（可以继续，之后可能出错）、成功、信息。

### 3.8 状态颜色

【查到】[Semantic Colors](https://www.sap.com/design-system/fiori-design-web/v1-139/foundations/best-practices/ui-elements/how-to-use-semantic-colors)：五种语义色（负面、警示、正面、中性、信息），只在需要表达这层含义时使用，不做装饰；同一颜色在所有场景含义相同；颜色必须配文字。Aham 的「6px 点 + 文字」规则与此一致。

### 3.9 选择控件选型

【查到】[Which Selection Control to Use](https://experience.sap.com/fiori-design-web/v1-94/which-selection-control-to-use)，按候选条数和识别方式选：

单选：

| 用户靠什么识别选项 | 2–12 条 | 13–200 条 | 200–1000 条 | 1000 条以上 |
|---|---|---|---|---|
| 一个值 | 下拉选择或组合框 | 组合框，只能选候选值 | 输入框带联想 + 选择弹窗 | 输入框带联想 + 值帮助弹窗 |
| 两个值 | 两列下拉或组合框 | 组合框，只能选候选值 | 输入框带联想 + 选择弹窗 | 输入框带联想 + 值帮助弹窗 |
| 3–4 个值 | 输入框带联想 + 选择弹窗 | 同左 | 同左 | 输入框带联想 + 值帮助弹窗 |
| 4 个以上值 | 输入框带联想 + 表格选择弹窗 | 同左 | 同左 | 输入框带联想 + 值帮助弹窗 |
| 要按条件或范围缩小 | 输入框带联想 + 值帮助弹窗 | 同左 | 同左 | 同左 |

多选把「下拉/组合框」换成「多选组合框」，把「输入框」换成「多值输入框」，其余相同。该页没有讲单选按钮、复选框、开关和分段按钮的选型【未查到】。

### 3.10 表格选型

【查到】[Grid Table](https://www.sap.com/design-system/fiori-design-web/v1-96/ui-elements/grid-table/usage)：

- 响应式表格是默认表格，适合按整行处理。
- 网格表格用于单元格级对比、大数据量（1000 行以上），只用于桌面和平板。
- 树形表格用于层级数据。
- 所有行同高；桌面默认 compact，可加 condensed 显示更多行，condensed 不能单独用，也不能和 cozy 同时用。
- 勾选框不禁用；操作失败时再提示。

### 3.11 打印与输出

【查到】[Output Management](https://www.sap.com/design-system/fiori-design-web/v1-145/ui-elements/output-management/usage)：

- 输出是嵌在单据页里的一张表，每行是一次输出，列有：状态、发送时间（立即或定时）、输出类型、接收人、渠道（打印机、邮件、EDI）、模板和语言、附件、预览。
- 预览统一是 PDF。
- 输出状态五种：准备中、待输出、处理中、已完成、出错。出错可以重发、设为完成、查看日志。
- 该页没有规定「打印」按钮放在哪【未查到】。

### 3.13 Fiori 与 Aham 现状对照

| 主题 | Fiori | Aham 现状 | 差距 |
|---|---|---|---|
| PC 行高 | compact 32px | 列表默认 44px（DESKTOP §2） | 需要改 |
| 显示态与编辑态同版式 | 有 | 7.5 已照做（WORKBENCH §4.2） | 一致 |
| 保存按钮位置 | 页脚工具栏 | 7.5 在页脚，7.6 在固定标题区 | 两版矛盾，需定一个 |
| 整页一个主按钮 | 有 | DESKTOP §1「同一操作范围只有一个主按钮」 | 基本一致 |
| 标签位置 | 推荐上方 | 7.5 左侧，7.6 上方 | 7.6 一致 |
| 必填星号只在编辑态 | 有 | 7.5 已有（WORKBENCH §4.1） | 一致 |
| 失焦校验 + 保存时全量校验 + 消息列表 | 有 | 7.5 已有（WORKBENCH §4.4） | 一致 |
| 草稿自动保存、离开三选一 | 有 | 有覆盖冲突弹窗（§4.2），没有草稿规则 | 缺 |
| 编辑锁定 | 有 | 没有 | 缺 |
| 页型选择规则 | 有 | DESIGN §8.3 有页型，没有按业务场景选页型的规则 | 缺 |
| 新建弹窗门槛（少于 8 个必填） | 有 | 有新建弹窗（WORKBENCH §12.6），没有字段数门槛 | 缺 |
| 选择控件按条数选型 | 有 | 有下拉、组合框、命令菜单，没有选型表 | 缺 |
| 单据状态生命周期 | 有输出状态、编辑状态 | 有状态点写法，没有定义单据从草稿到作废的状态和每个状态可用的操作 | 缺 |
| 打印与输出 | 有输出管理 | DESIGN §8.11 一行 `@media print` 规则 | 缺 |

## 4 规划草案

分 4 个阶段。阶段 1 只整理，不改外观，方便对照前后差异。

### 4.1 阶段 1：结构整理

- 规则文档合并成一套。建议结构：基础（颜色、字体、间距、图标）、组件、管理软件模式（列表、单据、查询、打印）三部分。7.5 和 7.6 的单据版式只留一种，版本说明移到 CHANGELOG。
- CSS 变量统一成一套前缀，全部由 tokens.json 生成，去掉手工同步。
- 清掉写死值（A3），lint 增加「字号不低于 12px」「只用令牌值」两条检查。
- 范围收窄：本轮只维护网页管理界面，其他范围的处理见 7.1（是否同意见问题 6）。
- 原则改写：DESIGN §0 的铁规按 7.4 改写，旧规则与新做法冲突时以新做法为准。

验收：页面截图与整理前逐像素比较，差异只来自 A3 的修正。

### 4.2 阶段 2：视觉调整

- 密度：PC 默认行高从 44px 改为问题 4 选定的值；表头与行同高；控件 32px，工具栏 28px。
- 线条：分隔线改用半透明黑，分 2–3 档。
- 底色：改为低饱和暖灰，取值初稿见 7.2。
- 颜色：强调色放宽为三组，规则见 7.3。
- 单据页：去掉卡片套小节块和蓝竖条，分区只用标题和留白。可改值的虚线、核对值的浅黄底改为只在编辑态或悬停时出现。
- 圆角：控件 6px，浮层 8–12px，胶囊只留给头像和计数。
- 图标：默认描边 1.5。

验收：列表、单据、设置三类页面的亮色和暗色截图，1280、1440、1920px 三档宽度。

### 4.3 阶段 3：管理软件交互规范

按 Fiori 补齐第 3.13 节标「缺」的 7 项，写成新章节：

1. 页型选择：列表、工作清单、单据页、按单号直达、向导、新建弹窗，各写适用条件。
2. 单据生命周期：定义草稿、已提交、审批中、已退回、已生效、已作废等状态（具体状态名要按你的业务确认），每个状态列出可用操作和可改字段。
3. 录入与修改：整页编辑、分区编辑、弹窗编辑的选用条件；按钮名称；离开保护。
4. 草稿与锁定：是否自动保存、保存间隔、离开时的选项、锁定和接手规则。
5. 必填与校验：沿用 7.5 已有规则，补「什么时候用警告、什么时候用错误」的判断条件。
6. 控件选型表：把 3.9 的表改写成 Aham 的控件名，补单选按钮、复选框、开关、分段按钮、日期、数字步进的选用条件。
7. 查询与打印：列表筛选栏、保存的筛选视图、导出；打印预览、打印模板版式、输出记录和输出状态。

### 4.4 阶段 4：示例与验收

- 选一张典型单据（建议用你最常做的业务单据，例如采购订单或报价单），做出列表、新建、编辑、提交、审批、打印预览 6 个页面，覆盖所有状态。
- 每个页面检查长名称、空值、错误、只读、保存失败五种情况。
- 视觉验收和流程验收分别记录。

## 5 待拍板的问题

1. **底色冷暖**：已定。改暖，不用 Claude 的米黄。取值初稿见 7.2，待看样张确认。
2. **强调色**：已定。放宽为不止一个颜色。主色是否保留钢蓝 `#336EE8`，我推荐保留，理由是 ORIGIN.md 写明 Word、PPT、Voice、Survey 共用这套取值。方案见 7.3。
3. **衬线字体**：继续全面禁用，或只在长文和 AI 输出里用。我推荐管理界面继续禁用。
4. **PC 默认行高**：32px（SAP compact）、36px、44px（现状）。我推荐 36px 作默认、32px 作紧凑档，理由是 7.6 的 44px 是你在 RFQ 样板里确认过的，36px 改动幅度小一些；如果你接受更紧凑的效果，可以直接用 32px。
5. **保存按钮位置**：固定标题区（7.6），或页脚（7.5 和 Fiori）。我推荐 7.6 的固定标题区，理由是两种做法都保证按钮一直可见，7.6 已在 RFQ 样板里确认过。
6. **范围**：本轮只做网页管理界面，或继续维护 4 条轨道。我推荐只做网页管理界面。
7. **草稿**：你的业务系统后端是否支持自动保存草稿和编辑锁定。这决定 4.3 第 4 项写成必选规则还是可选规则。
8. **打印**：打印的对象是浏览器里的单据页，还是单独的 PDF 模板（如套打的纸质单据）。这决定 4.3 第 7 项的写法。

## 7 修订内容

### 7.1 现有范围

另有一组面向消费类应用的组件：DESIGN §2.9「媒体与对话」，含播放器、逐句转写、头像、对话输入框、附件卡，来自 AhamVoice。

关于「卡通」：这几套范围都没有卡通风格，仓库里没有插画、吉祥物或彩色图形。它们的区别只在输出介质（网页、Mac 应用、Office 文档、邮件）和页面类型。如果你说的是能否「打通」，几套范围已经共用同一份 tokens.json 的颜色和字体，可以合并的部分是：网页内两套样式合成一套、两版单据只留一版。

- macOS 应用轨和邮件轨没有实现，规范里先删掉，需要时再加。
- Office 轨保留 aham-ui-office.md 一个文件，只跟着颜色和字体同步。
- §2.9 媒体与对话组件移出管理软件规范，单独存放。

### 7.2 暖灰底色初稿

思路：内容区保持纯白，只把面板、分隔线、文字的灰调成暖灰；饱和度控制在 Claude 米黄的一半以下，看起来是「带一点暖的灰」，不发黄。

【读到】【查到】作比较的两组值：Aham 现在的面板 `#F3F3F3`（饱和度 0%）；Anthropic 品牌色 Light `#faf9f5`（色相 48°，饱和度 33%）、Light Gray `#e8e6dc`。

初稿（色相 40° 左右，饱和度 4%–15%，对比度是我用 WCAG 公式算的）：

| 用途 | 现值 | 初稿 | 对白底对比度 |
|---|---|---|---|
| 内容底 | `#FFFFFF` | `#FFFFFF`（不变） | — |
| 面板、侧栏 | `#F3F3F3` | `#F6F5F3` | 1.09 |
| 悬停、选中 | `#E7E7E7` | `#EDEBE7` | 1.19 |
| 分隔线 | `#E7E7E7` | `#E5E2DC`，或半透明暖黑 | 1.29 |
| 主文字 | `#262626` | `#262522` | 15.33 |
| 次文字 | `#6E6E6E` | `#6B6862` | 5.55 |
| 占位文字 | `#9B9B9B` | `#97938B` | 3.06（只用于占位，与现状同级） |

暗色要单独取值，阶段 2 和亮色一起出样张。这组值是初稿，要在 1440px 的列表页和单据页样张上看过再定。

### 7.3 强调色放宽

分三组颜色，每组规定能用在哪：

| 组 | 颜色 | 用途 | 限制 |
|---|---|---|---|
| 主色 | 钢蓝 `#336EE8`（主按钮底 `#164EC3`） | 主按钮、链接、焦点、当前页签 | 和现在一样 |
| 状态色 | 成功、警示、错误、信息 4 色，饱和度比现在高 | 状态点、状态图标、校验信息、消息条 | 必须配文字；只用在文字、图标、6px 点和浅底上，不做整行底色 |
| 分类色 | 6 色左右 | 小图标、文件类型、标签、头像、图表系列 | 只用在 16px 以内的图标、标签文字和图表；同一页不超过 6 种 |

状态色初稿（对白底对比度）：成功 `#1F7A4D`（5.32）、警示 `#A15C07`（5.19）、错误 `#B42318`（6.57）、信息用主色。现值成功 `#5A7A60`、警示 `#8A7333` 偏灰，小图标上不容易辨认，这是放宽的主要理由。

分类色的具体取值在阶段 2 出样张时定，要求每个颜色对白底至少 3:1（WCAG 对图形的要求），并单独给暗色取值。

### 7.4 要改写的旧规则

【读到】DESIGN §0「铁规总览」里，下面几条和新方向冲突，建议改写：

| 旧规则 | 改为 |
|---|---|
| 蓝是唯一色相 | 按 7.3 的三组颜色使用 |
| 状态 = 6px 点 + 文字，绝不用徽章、色块 | 保留「点 + 文字」为默认；允许状态色图标；仍不用整行色块 |
| 语义色极弱，仅真风险 | 状态色提高饱和度，用于所有状态表达 |
| 身份锚点：单蓝 + 三层灰 + 冷色的纸（§1.1） | 主色蓝 + 暖灰 + 分组用色 |
| PC 列表默认 44px（DESKTOP §2） | 按问题 4 的结论 |
| 单据正文卡片描边、小节块、蓝竖条（WORKBENCH §4.1） | 删除，分区只用标题和留白 |
