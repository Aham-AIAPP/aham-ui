# Aham 9.0 样板自查记录

日期 2026-10-25。对象是 9.0 分支的 5 个样板页：外框（shell）、列表（list）、记录详情（record）、工作清单（worklist）、设置（settings）。判据是 [rules/9-验收.md](../rules/9-验收.md) 9.7 的 S1–S12。

## 1 方法

- 截图：5 页 × 亮色和暗色 × 1440、1024、390 三种宽度，共 30 张。用本环境的 Chromium 截取，设备像素比 1。
- 自动统计：在浏览器里读取屏幕内每段文字的计算字号、文字颜色、图标尺寸、数据行高度、横向滚动、被裁掉的文字、渐变和静止阴影。脚本不在仓库里，结果写在下文。
- 人工看图：逐张看截图，找自动统计查不出的问题。
- 键盘：用 Playwright 只按键盘走 G 加字母跳转、⌘/Ctrl + K、⌘/Ctrl + B 和 ?。
- 对照 Linear：用户提供的 Linear 截图按 1.66 倍缩回实际尺寸，和列表样板同比例上下拼接，见 [img/linear-aham9-same-scale.png](img/linear-aham9-same-scale.png)。比例的算法见 [Linear字体字号-调研.md](Linear字体字号-调研.md) 2.1。

标记沿用调研文档：【实测】是本次测量的结果，【推测】是我的判断。

## 4 和 Linear 同比例对照

同比例拼图里，上半部分是 Linear 截图，下半部分是 Aham 列表样板。

一致的地方：

- 侧栏比内容区深一档，当前项用灰底，不用主色。
- 列表一行一个对象，不显示表头，按阶段分组，分组行有底色。
- 行高接近：Linear 约 48px，Aham 44px。
- 行首是编号和阶段图标，行尾是标签、日期和头像。标签是描边胶囊加圆点。
- 页眉只有一条细线分隔，按钮不加框。

有意保留的差别：

| 差别 | Linear | Aham | 理由 |
|---|---|---|---|
| 编号和日期的字号 | 13px，颜色更淡 | 12px，`--wb-muted` | 中文名称字面比英文高，12px 才拉得开层级，见调研 T2 |
| 默认主题 | 深色 | 亮色 | 1.3 已定：默认深色属于 Linear 的品牌选择 |
| 主色 | 靛蓝 | 钢蓝 `#336EE8` | 同上 |
| 输入框描边 | 很淡 | 对白底 3.96:1 | WCAG 对控件边界的要求，冲突次序第 1 项 |

没有跟进的差别：

- Linear 的分组行右侧有「+」，可以在该组里直接新建。Aham 没有做。【推测】业务系统新建时通常要填必填项，分组里直接新建的用处要在 FDE 试点里看。
- Linear 的侧栏有收藏和团队两组。Aham 的侧栏只放业务对象，收藏留给产品决定。

## 6 交互层一轮（2026-10-25）

方法：用 Playwright 在 Chromium 里测 examples/ 下全部样板页，按 rules/11-交互.md 11.7 逐条取值。测试脚本不进仓库。结果全部是【实测】。

| 验收项 | 结果 |
|---|---|
| 描边按钮静止、悬停、按下的底色 | `#FFFFFF`、`#F3F3F2`、`#EBEBEA`，按下 `scale(0.97)` |
| 菜单打开时触发按钮 | `aria-expanded=true`，底色 `#EBEBEA`；账户按钮 `#D5D4D3` |
| 菜单出现 | 100ms 内 `opacity` 0 到 1，缩放 0.97 到 1 |
| 菜单消失 | 加 `data-leaving` 后隐藏，焦点回到触发按钮 |
| 命令面板 | 第一帧 `opacity` 为 1 |
| 弹窗遮罩下的侧栏 | `#8E8D8D` |
| 触屏（模拟 iPhone 13） | 点过的按钮不留悬停色；分栏弹窗铺满 390×664 |
| 减少动态效果 | 按下和菜单出现时 `transform` 为 `none`，淡入保留 |
| 控制台报错 | 8 个样板页都没有 |

发现并改掉的问题：

- 暗色主按钮悬停 `#4A7FEB` 上白字只有 3.80:1，改为更深的 `#2A62D6`（5.50:1），按下 `#2357C4`（6.50:1）。
- 交互样板里的表格撑破了列宽，加 `min-width:0`。
- 分栏弹窗当前分类用了布尔值的 `aria-current`，改为 `page`。

### Mac 本机测试（2026-10-25）

在用户的 MacBook 上用 Chrome for Testing 151 和 Safari 27.0.1 各测一遍，视口 1440×900，2 倍像素。两个浏览器都是自动化点击，没有手点。【实测】

| 验收项 | Chromium | Safari |
|---|---|---|
| `(hover: hover) and (pointer: fine)` | true | true |
| 按钮三态和按下 0.97 | 通过 | 通过 |
| 菜单出现、消失、焦点回到按钮 | 通过，约 160ms 到 1 | 通过，约 156ms 到 1 |
| 偏好弹窗出现、遮罩下侧栏 `#8E8E8D` | 通过 | 通过 |
| ⌘/Ctrl + , 打开偏好设置 | 自动化下通过 | 不通过 |
| 命令面板第一帧 `opacity` 为 1 | 通过 | 通过 |
| 悬停提示 500ms、相邻立即 | 503ms、17ms | 509ms、立即 |
| 设置页保存栏 | 通过 | 通过 |
| 减少动态效果 | 模拟下通过 | 没测 |

按结果改的：

- Safari 和 Chrome 在 macOS 上把 ⌘, 留给浏览器自己的设置，网页收不到。删去这个快捷键，偏好设置从账户菜单和命令面板打开。
- Safari 里鼠标打开偏好弹窗后，当前分类显示焦点框。改为鼠标打开时焦点放在内容区，键盘打开时才放在当前分类。改后只在 Chromium 复测过。
- 页面右侧的按钮打开的菜单向右伸出约 230px。`openPopover()` 默认改为按钮在右半边时右对齐。
- 规则补写：浮层和弹窗消失时淡出并缩回 0.97。

留着观察的：Chromium 第一次打开菜单和偏好弹窗时各有一次约 150ms 没出新帧，之后重复 5 次没再出现，Safari 没出现。

没做的：手点，系统「减少动态效果」打开后的实测，触屏真机。
