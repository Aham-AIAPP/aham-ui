# 3 控件

本章落实设计理念的原则 3、8、9、10。

每个控件的状态见 [examples/controls.html](../examples/controls.html)，结构和键盘见 [components/](../components/)。

## 3.2 按钮

| 类型 | 写法 | 用在 |
|---|---|---|
| 主按钮 | `.wb-btn.primary` | 页面上最主要的操作：提交审批、保存、创建。每个当前任务层一个，弹窗有自己的主操作 |
| 普通按钮 | `.wb-btn` | 其他操作：编辑、打印预览、撤回 |
| 文字按钮 | `.wb-btn.ghost` | 次要且常用的操作：取消、工具栏里的开关 |
| 危险按钮 | `.wb-btn.danger` | 只出现在确认弹窗里：删除、作废。页面上的删除放进「更多」菜单，用红色文字 |
| 图标按钮 | `.wb-icon-btn` 或 `.wb-btn.icon-only` | 含义通用的操作：更多、关闭、搜索、刷新、导航开关、面板开关 |

- 优先文字按钮；图标能加快识别时允许图标加文字，间距用 `--wb-icon-gap`（6px）。图标不重复朗读。只有图标时必须有可访问名称。AI 操作保留 `ai` 图标说明来源。
- 去掉底色的文字按钮（`.wb-btn.ghost`）放在正文开头时，向左移出自己的内边距，文字和上方标题左对齐。
- 只用图标的按钮必须有 `aria-label`，悬停时显示名称（`data-tooltip`）。业务操作（提交、审批、导出、分配）写文字，不做成图标按钮。
- 同一个按钮可以按状态换形式。例如列表的「筛选」：没有条件时是文字按钮，有条件后筛选行出现，按钮缩成图标。
- 按钮文字写动作本身，两到四个字：保存、提交审批、复制为新报价。确认弹窗的按钮也写动作（删除、作废、撤回），不写「确定」「是」。
- 确认弹窗和页脚工具栏里，取消在左、执行在右。
- 同一个动作全系统用同一个词：改已有的内容写「编辑」，创建一个对象写「新建」，在表格或列表里加一行写「添加」，把已有对象放进另一个对象写「加入」。词表见 [1-总则.md](1-总则.md) 1.4。
- 动作词有两种读法时换词。例如「归入」读不出是移动还是复制，改写「加入项目」；按钮写全动作和对象，例如「添加记录」。不用只写「＋」的按钮，也不在文字前加「＋」：「添加联系人」。
- 「更多」菜单和折叠区只放低频操作，例如删除、转派、导出。每天要用的操作直接放在页面上。

## 3.3 控件状态

控件有五种状态：可用、禁用、只读、隐藏、忙碌。按下表判断，规则来自 SAP Fiori 的「UI Element States」。

| 情况 | 状态 | 例子 |
|---|---|---|
| 当前用户在这个角色或这个单据状态下永远用不了 | 隐藏 | 没有审批权限的人看不到「批准」；已生效的报价单没有「编辑」 |
| 用户看得出为什么不能用，也知道怎么让它能用 | 禁用（`disabled`） | 明细表没选中行时，「删除行」禁用 |
| 用户看不出为什么不能用 | 保持可用，点击后说明原因 | 必填未填写时点「提交审批」，弹出消息列表并定位到第一个问题 |
| 编辑态里不能改、但需要看的字段 | 只读：显示成文字，不做成禁用的输入框 | 单号、创建人、由明细算出的合计 |
| 暂时不能改、满足条件后可以改的字段 | 禁用的输入框，旁边写条件 | 「先选客户」之后才能选联系人 |
| 正在执行 | 忙碌：`aria-busy="true"` 并禁用，完成后恢复 | 保存中的「保存」 |

- 表格行前的勾选框永远可用。勾选的行里有不能处理的，执行时再说明，规则见 [6-反馈.md](6-反馈.md) 6.4。
- 批量操作条只在有勾选时出现，没有勾选时整条不显示，不做成一排禁用按钮。
- 禁用的控件不能取得焦点。需要让用户读到原因时，把原因写在控件旁边，不放在禁用控件的悬停提示里。

## 3.4 工具栏

工具栏指一组并排的操作按钮：单据头右侧、页脚、明细表标题行、列表批量条。

- 每个工具栏最多一个主按钮。同一任务层只有一个主操作；弹窗可有独立主操作。
- 从左到右：普通按钮（常用的靠近主按钮）→ 主按钮 → 「更多」。
- 宽度不够时，离主按钮最远的普通按钮先收进「更多」，主按钮最后收。
- 「更多」菜单里的顺序和按钮在工具栏上的顺序一致。删除、作废放在菜单最后，前面加一条分隔线，用红色文字。
- 一个工具栏最多 3 个可见的普通按钮，其余进「更多」。
- 明细表标题行的工具栏只放作用于这张表的操作：添加行、删除行、导入、导出、显示选项。
- 工具栏右对齐。只有页脚工具栏的消息按钮放在最左。

和 Fiori 的两处差异：Fiori 把强调按钮放在一组按钮的最左，把「取消」放在「保存」右侧；Aham 沿用网页常见的写法，主按钮在右，取消在左。

## 3.5 输入框

- 标签在上，值在下，标签和值之间 4px。标签用次要文字色，不加冒号。
- 必填在标签后加红色星号，只在编辑态显示。显示态里必填项未填写时，值的位置写红字「未填写」。
- 输入框宽度跟随表单列宽。数字、金额右对齐，用等宽数字（`.wb-tnum`）；单位写在框外右侧（`.wb-unit`），不放进框里。
- 占位文字写格式示例（「姓名 · 部门」「YYYY-MM-DD」），不写「请输入」，也不能代替标签。
- 系统生成的值（负责人、创建时间、单号）在编辑态也显示成文字，不做成禁用的输入框。
- 禁用的输入框只用在「暂时不能改、条件满足后可以改」的情况，旁边写明条件。
- 多行文本在单据里随内容长高，从一行开始；在弹窗里固定 3 行。

## 3.6 选择控件选型

下表按 SAP Fiori 的「Which Selection Control to Use」改写，选项数量指用户可以选的候选值个数。Fiori 的原表从 2 个选项起就用下拉；「2–5 个用单选组」是 Aham 加的，理由是选项少时全部摆出来，少点一次。

**单选：**

| 用户靠什么认出选项 | 2–5 个 | 6–12 个 | 13–200 个 | 200 个以上 |
|---|---|---|---|---|
| 一个值（如币种） | 单选组 | 下拉 | 选择菜单（带搜索） | 输入框带联想 + 值帮助弹窗 |
| 两个值（如编码 + 名称） | 单选组 | 下拉，选项写「编码 · 名称」 | 选择菜单（带搜索） | 输入框带联想 + 值帮助弹窗 |
| 三个及以上的值 | 选择弹窗（表格） | 选择弹窗（表格） | 选择弹窗（表格） | 值帮助弹窗 |
| 要按条件缩小范围 | 值帮助弹窗 | 值帮助弹窗 | 值帮助弹窗 | 值帮助弹窗 |

**多选：** 2–5 个用复选框组；6–200 个用选择菜单的多选模式（`createCommand` 的 `checked`）；200 个以上用值帮助弹窗。

**其他：**

| 场景 | 控件 |
|---|---|
| 是或否，保存时生效 | 一个复选框 |
| 是或否，改了立即生效（设置页） | 开关 |
| 切换同一份内容的看法（标准 / 紧凑，列表 / 看板） | 分段按钮 |
| 切换一个页面上的两个对象（项目的概况是项目本身，任务是另一组对象） | 页签，一页最多 2 个。同一个对象的内容一页到底，不用页签切分；单据页和记录详情页不用页签；附件跟随它说明的条目，不单独做页签 |
| 日期 | `<input type="date" class="wb-field">`，显示成 YYYY-MM-DD |
| 日期范围 | 两个日期框，写成「从 … 到 …」，后一个不早于前一个 |
| 数量、金额 | `.wb-field.is-number`，`inputmode="numeric"` 或 `"decimal"`，不用上下箭头的步进器 |
| 人员、客户等大量记录 | 选择菜单（带搜索），超过 200 个用值帮助弹窗 |

参考实现：选择菜单是 `openPicker()` 和 `createCommand()`。**选择弹窗（表格）、值帮助弹窗、输入框联想没有参考实现**，产品需要时按本表和 3.7 的条件自行实现，并补进本仓库。

## 3.7 值帮助弹窗

值帮助弹窗用于候选值多于 200 个，或者要先按条件缩小范围再选的字段，例如物料、供应商、会计科目。规则来自 SAP Fiori 的「Value Help Dialog」。

**入口**

- 输入框右侧放一个图标按钮打开弹窗，F4 也能打开。
- 输入框本身带联想：输入 2 个字以上，下方列出最多 10 条匹配项。
- 输入框可以直接写条件，离开输入框时转成条件标签：`=A100` 等于，`A100...A199` 介于，`<500` 小于，`>500` 大于，`!A100` 不等于，`*泵*` 包含。

**弹窗结构**（宽 880px，`--wb-dialog-wide`）

1. 标题：「选择 <字段名>」。
2. 两个页签：「搜索并选择」「定义条件」。字段只允许选已有的值时，只有第一个页签。
3. 「搜索并选择」：上方一个搜索框和一条筛选行（默认收起，「显示筛选」展开）；下方是结果表格，第一列是值，第二列是说明，最多 6 列。
4. 「定义条件」：每行一个条件，「包含 / 排除」+ 运算符 + 值，可以加多行。运算符有：等于、不等于、介于、包含、开头是、结尾是、小于、不大于、大于、不小于、为空。
5. 底部是已选区：每个已选值或条件是一个标签，可以单独移除；右侧「全部清除」。
6. 按钮：取消、确定。

**行为**

- 单选：点表格里的一行即选中并关闭弹窗，不需要「确定」。
- 多选：表格第一列是勾选框，勾选的值同步到已选区；点「确定」才写回字段。
- 打开时，字段里已有的值和条件预先放进已选区。
- 搜索结果超过 200 条时，表格只显示前 200 条，上方写「显示前 200 条，缩小搜索范围可以看到更多」。

## 3.8 状态

- 写法：6px 圆点加文字，`<span class="wb-status" data-tone="success"><b></b><span>已生效</span></span>`。
- `data-tone` 取 `draft`（次要文字色空心圆）、`wait`（信息色空心圆）、`info`、`success`、`warning`、`danger`，不写为无色实心圆。各状态用哪个色见 [2-视觉.md](2-视觉.md) 2.2。
- 状态文字用正文色，只有圆点有颜色。
- 列表里的状态列、单据头、详情页都用同一种写法，不用彩色徽章或整行底色。

## 3.9 标签和分类

- 标签用来标类别，不能点击。能点击的筛选条件用 `.wb-chip`（见 [4-页面.md](4-页面.md) 4.4）。
- 标签是描边胶囊（`.wb-tag`）：高 20px，左右内边距 8px，1px `--wb-line` 描边，左侧 6px 分类色圆点，文字 12px、`--wb-ink-2`，不铺底色。没有分类色的标签（`.wb-tag.is-plain`）不画圆点。
- 一个值最多带两个标签。标签多于两个时，写前两个加「+ N」。
- 标签文字两到四个字。
- 列表行里的标签靠右排在日期和人员之前，同一列表里标签的右边缘对齐。

## 3.10 提示条

提示条（`.wb-strip`）说明整张单据或整个页面的状态，放在单据头下面、正文上面。

| 色调 | 用在 |
|---|---|
| `info` | 审批中、正在处理、需要知道的说明 |
| `success` | 已生效、已完成 |
| `warning` | 已退回（写退回原因）、即将过期 |
| `danger` | 阻止提交的原因，例如必填未填写 |
| 不写 | 已作废、已关闭这类没有好坏的状态 |

- 一页最多一条提示条。状态变了就换掉内容，不叠加。
- 提示条可以带一个按钮，例如「去填写」。
- 单个字段的问题标在字段上（字段状态），不放进提示条。
- 说明「等谁、做什么」用下一步提示条（3.13），不用提示条。两者同时出现时，提示条在上。

## 3.11 头像

- 人员一律显示圆形头像加姓名：负责人、评论人、指派人、提问人、确认人。写法是 `personHTML(name)`，生成 `.wb-person`。
- 头像写姓名的第一个字。底色是分类色的 18%，文字用正文色，序号由 `avatarCat()` 从姓名算出，同一个人在全系统同一个颜色。
- 没有指定人员时，显示虚线空心圆和「未指定」，文字用次要文字色。
- 多人时头像叠放在 `.wb-people` 里，姓名用顿号连接。超过 3 人时写前 3 人，后面加「等 N 人」。
- 侧栏底部的当前用户用 24px 的 `.wb-avatar`；动态、评论和列表单元格里用 20px 的 `.wb-avatar-xs`。
- 单行列表（[4-页面.md](4-页面.md) 4.3）的人员只显示 20px 头像，不写姓名，头像带 `title` 和 `aria-label` 写出姓名。详情页、属性栏、动态和评论仍显示头像加姓名。写法是 `personHTML(name, { compact: true })`。
- 头像单独出现时（单行列表、叠放超出宽度），必须带 `title` 和 `aria-label` 写出姓名。

## 3.12 阶段条和时间线

**阶段条**用来画一个对象要走的多阶段流程，放在标题下方。

- 写法：`<ol class="wb-stages">`，一段一个 `<li>`，`data-state` 取 `done`（已完成）、`current`（进行中）、`todo`（没开始）、`off`（不进行）。
- 每段第一行写阶段名（`.wb-stage-name`），第二行写人和日期（`.wb-stage-sub`），例如「林悦 · 10-12」。没开始的段第二行留空。
- 每段上方是一条 2px 的线：已完成用成功色，进行中用主色，没开始用 `--wb-line`。
- 状态不只靠颜色：已完成的段名前打勾，进行中的段名字重 500，不进行的段用虚线并划掉名称。
- 每段写 `aria-label`，格式是「阶段名：状态，说明」，例如「立项：已完成，林悦 10-12」。
- 只画能走完的阶段。本期产品不做的阶段不画进阶段条。
- 阶段条最多 8 段。640px 及以下时阶段条横向滚动，段宽不小于 48px。

**时间线**用来画一个对象自己的流转记录，例如一条需求从提出到验证。

- 写法：`<ol class="wb-timeline">`，一项一个 `<li>`，`data-state` 和阶段条相同。每项写名称（`.wb-timeline-name`）和一行说明（`.wb-timeline-sub`）。
- 时间线竖向排列，放在记录详情页的右侧属性栏里。
- 阶段条和时间线都用状态色（成功、信息），不用分类色。

## 3.13 下一步提示条

- 有流程的对象，标题下方放一条下一步提示条 `.wb-next`，写等谁、做什么、计划日期。例如「等王卓确认验收标准 · 计划 2026-10-25」。
- 有流程的判据：对象有状态或阶段字段，并且当前状态要某个人做一件事才能往下走。客户（有客户状态）、商机、报价单、合同、需求、场景卡算有流程；联系人、产品、部门这类只登记信息的对象没有。
- 等的人是当前用户时写「你」：「等你确认验收标准」。
- 其他写法：等几个人时写「等王卓、陈思确认（1/2）」；等客户方时写人和组织「等张工 · 远川提供设备清单」；AI 在处理时写「AI 正在整理，完成后等你确认」；过了计划日期时日期写成「已逾期 3 天」，加 `.is-overdue` 用错误色。
- 不写不指明人的说法，例如「待处理」「处理中」。说不出在等谁时，写清楚卡在哪一步。
- 条上可以放这一步的按钮，最多一个。这一步就是页面的主操作时用主按钮，其他情况用普通按钮。等别人时这个按钮是「提醒」，规则见 [6-反馈.md](6-反馈.md) 6.11。
- 没有在等的人时（已完成、已关闭）不显示下一步提示条，状态写在摘要行里。
- 一页最多一条下一步提示条。

## 3.14 输入区

- 评论、回答和补充说明用同一个输入区 `.wb-composer`：文字、文件和录音放在同一个框里。
- 框底部是工具条：左侧放「文件」「录音」两个文字按钮，右侧放发送按钮。
- 文件可以拖进输入区（`initDropZone()`），拖入时整个框加深描边。已加的文件在文字下方排成一行（`.wb-composer-files`），每个文件写类型色图标、名称、大小和移除按钮。
- 录音保存原始音频，网页不做语音转文字。需要文字时，用户用输入法的语音输入。录音没有参考实现。
- 附件跟随它说明的问题或条目，放在该条目下的输入区里，常显在主区。不集中到单独的附件区，也不收进页头的按钮。
- ⌘/Ctrl + Enter 发送，单按 Enter 换行，参考实现是 `initComposer()`。

## 3.15 阶段图标

阶段图标（`.wb-stage-icon`）是 16px 的圆形图标，在列表行里用一个图标表示对象走到了哪一段。做法参考 Linear 列表行里的状态图标。

| 状态 | 画法 | 颜色 |
|---|---|---|
| 没开始 | 虚线空心圆 | `--wb-faint` |
| 进行中 | 实线圆，里面按已完成的比例画扇形 | 主色 |
| 已完成 | 实心圆加白色对勾 | 成功色 |
| 退回或受阻 | 实线圆，中间一条横线 | 警示色 |
| 不进行 | 实线圆加斜线 | `--wb-faint` |

- 写法：`stageIconHTML({ state, done, total, label })`，生成 `<span class="wb-stage-icon" data-state="current" role="img" aria-label="方案评估：进行中，第 3 段，共 6 段">`。`done` 和 `total` 决定扇形的比例。
- 图标旁边不写阶段名时，`aria-label` 和 `title` 写出阶段名、状态和第几段。
- 列表按阶段分组时，分组行前放同样的阶段图标。阶段能手改时，数据行里的阶段图标是改阶段的入口（快捷键 S）；阶段由数据算出时，数据行里不再重复阶段图标，分组行已经写明。
- 详情页标题下方仍用阶段条（3.12）。阶段图标只用在列表行、关联记录和命令面板这类一行高的位置。

## 3.16 关键信息（记录详情页）

记录详情页标题下的一行 3–4 个数（`.wb-key-facts`），写判断推进要用的数：金额、计划日期、停留天数、下一步。参考实现见 [examples/parts-record.html](../examples/parts-record.html)。

- 一格一个 `.wb-key-fact`：第一行标签（`.wb-key-fact-k`，12px），第二行数（`.wb-key-fact-v`），第三行一句说明（`.wb-key-fact-s`，12px），例如「2026 年 · 还有 53 天」。值是一句话时用 `.wb-key-fact-text`，最多三行。
- 各格等宽，数一律 24px（`--wb-total`）、字重 600，不单独放大某一格，不加渐变底色。外框用 `--wb-line`，格子之间用 `--wb-line-soft`。
- 状态写在格上，颜色只表达含义：超期、停滞加 `.is-risk`（红）；缺了要补的值加 `.is-warn`（琥珀），值写「未填」「未安排」，说明行放补填的链接，例如「填写金额」；没有数据也不用补的加 `.is-muted`。
- 停留天数配一条进度（`.wb-key-fact-bar`）：`<i><b class="wb-fill-N"></b></i>` 后面写「停留 19 / 建议 14 天」，N 是停留天数占建议天数的百分比，超过 100 按 100 画，格子加 `.is-risk`。
- 最后一格是下一步（`.is-next`）：标签写「下一步 · 已逾期 2 天」，值写要做的事，下面写执行人和「处理」按钮（`.wb-key-fact-actions`）。逾期时整格加 `.tone-risk`，今天到期加 `.tone-warn`，这两种铺警示底色。没有下一步时值写「未安排」并加 `.is-warn`，下面给「新建任务」。
- 不放输入框；改值在属性栏里改。
- 1024px 及以下每行三格，下一步独占一行；640px 及以下每行两格。

## 3.17 带事件的阶段条

阶段条（3.12）的一种画法（`.wb-stage-track`）：除了阶段，还要看每条往来记录落在哪一段、停了多久时用。参考实现见 [examples/parts-record.html](../examples/parts-record.html)。

- 站点（`.wb-stage-stop`）写阶段名和一行说明：已过的写进站日期，当前的写「10-09 起 · 19 天」，没到的写建议停留天数，终点写计划日期。`data-state` 取 `past`、`now`、`future`、`end`、`won`、`lost`。
- 当前阶段那一段按停留时间拉长到其他段的 3 倍，停得久一眼能看出。
- 线 4px，站点 14px，记录点 8px。走过的站实心蓝，当前站实心蓝加一圈浅蓝，名称蓝色、字重 600；没到的站和签约站空心；赢单绿色，输单红色。
- 每条记录是线上的一个点（`.wb-stage-event`），按日期落在所在阶段里。上门拜访这类面对面的记录用实心点（`.is-strong`），其他用空心点。点上不写日期，日期和内容写在 `title` 里，悬停看。点可以链接到那条记录。
- 「今天」用一条 1px 虚线标在当前段里（`.wb-stage-today`）。
- 说明和图例不常驻，写进标题行右侧「?」按钮的悬停提示。线下（`.wb-stage-track-foot`）只写要提醒的话，例如最长一段没有记录的时间「10-09 到 10-26，17 天没有跟进」（`.wb-stage-track-gap`）。
- 位置用档位类：站点、点和「今天」用 `.wb-at-0` 到 `.wb-at-100`，已走过的线用 `.wb-fill-0` 到 `.wb-fill-100`。页面不写内联样式。
- 最少 680px 宽，窄屏横向滚动。

## 3.18 工作记录

记录详情页正文里的往来记录（`.wb-worklog`）：跟进、电话、拜访、回访、处理记录。规则见 [4-页面.md](4-页面.md) 4.8；参考实现见 [examples/parts-record.html](../examples/parts-record.html)。

- 还没完成的任务列在最上面（`.wb-worklog-open`），一行一条：计划日期、要做的事、执行人和编号、「处理」按钮。逾期的行加 `.is-overdue`。
- 下面是记录，最新的在上（`.wb-worklog-item`）：第一行写方式（字重 500）、事项标签、人、时间（`.wb-worklog-time`，12px）、所属对象，编号放在行尾（`.wb-worklog-code`，12px，普通字体）；然后是内容；再往下是「当前问题」「下一步」这类补充（`.wb-worklog-note`，左边 `--wb-muted` 标签）。
- 每条记录左边一个 24px 的类型圆标（`.wb-worklog-icon`，里面 14px 图标）：跟进浅蓝底蓝图标，面对面的记录（拜访、回访，`.is-strong`）实心蓝，任务灰底。圆标之间一条细线连起来。
- 靠这条记录完成的任务挂在这条记录下（`.wb-worklog-closed`）：前面一个绿色的 success 图标，写「同时完成任务」加任务内容，编号放进链接的 `title`，不再单独占一行。不靠记录就结束的任务（完成、取消）单独成行，加 `.is-task`；取消的再加 `.is-cancelled`，整条变灰。
- 最近 8 条直接显示，更早的折叠在「查看更早记录 · n 条」（`.wb-worklog-more`）里。
- 记录区窄于 960px 时一栏排：整条记录最宽 `--wb-body-width` 加 36px（圆标和间距），补充内容排在内容下面。960px 以上分两栏：左边是内容和「当前问题」这类补充，最宽 `--wb-body-width`，一行仍不超过 48 个字；右边 `.wb-worklog-side` 放下一步和同时完成的任务，占满剩下的宽度，宽屏时记录旁边不留空白。没有下一步、也没有同时完成任务的记录不写 `.wb-worklog-side`。
- 和页尾折叠的动态分开：动态只放系统记下的修改和事件。

## 3.19 还缺什么

一条提示（`.wb-gaps`），列出这条记录还缺的信息，例如「决策人」「为什么现在做」「竞争情况」。

- 放在标题下、关键信息上面。没有缺的就不显示。
- 标题写「还缺」或「待补信息」，后面每项一个圆角标签，鼠标停在上面显示该问对方的问题（`title`）。
- 缺的是信息，不是任务：要某个人去做的事写成下一步（3.13、3.16）。

## 3.20 处理面板

一件待办有几种处理方式时，用一个面板先选方式，再填这种方式要的内容（`.wb-handle`）。参考实现见 [examples/parts-record.html](../examples/parts-record.html)。

- 第一行是方式（`.wb-handle-modes`），每个方式一张卡片：名称加一句说明，例如「完成任务 · 记一条跟进，任务随之完成」「调整日期」「转派他人」「取消任务」。没有权限的方式不出现。
- 选中一种方式后只显示它的字段（`.wb-handle-fields`），其他方式的字段隐藏并停用，不随表单提交。
- 必填只留最少的一项，例如「办理结果」；其他带默认值，例如发生时间默认当前时间、执行人默认本人。常用日期给快捷按钮（`.wb-handle-chip-btn`）。
- 不常填的补充收在「补充……」折叠里（`.wb-handle-more`）。
- 字段下方写「提交后：……」（`.wb-handle-sum`），说明会记什么、哪条任务完成、会不会新建任务。提交按钮的文字跟着方式变：「完成任务」「确认调整」「确认转派」「取消任务」，取消用危险色。
- 同一件事全站一个面板：列表、首页、详情页的「处理」打开同一个面板（弹窗里是 `.wb-handle`，详情页里加 `.is-inline` 直接展开）。640px 及以下方式两列，按钮占满一行。
