# 6 反馈

本文件按 SAP Fiori 的消息处理（Message Handling）改写：按消息和什么有关、要不要用户决定，选不同的元素。

## 6.1 消息元素

| 元素 | 用在 | 消失方式 | 参考实现 |
|---|---|---|---|
| 轻提示 | 操作已经完成的确认：已保存、已提交、已复制 | 4 秒后自动消失，悬停或聚焦时暂停 | `toast()` |
| 提示条 | 整张单据或整个页面的状态、阻断原因 | 状态变了才换 | `.wb-strip` |
| 字段状态 | 单个字段的错误或提醒 | 改对后消失 | `initObjectPage()` |
| 消息列表 | 编辑态里全部字段的错误和提醒 | 用户关闭；问题解决后条数减少 | `initObjectPage()` |
| 消息框 | 不可撤销的操作之前问一次；页面上放不下的错误 | 用户选择后关闭 | `openConfirm()` |
| 批量结果 | 批量操作有失败的 | 用户关闭 | `showBatchResult()` |
| 空状态 | 没有数据、筛选没有结果、没有权限 | 有数据后消失 | `.wb-empty` |
| 占位加载 | 首次加载 | 内容到了就替换 | `.wb-skeleton` |

判断顺序：

1. 和某个字段有关 → 字段状态，编辑态里同时进消息列表。
2. 要用户做决定才能继续 → 消息框。
3. 说明整张单据现在的状态 → 提示条。
4. 告诉用户刚才的操作成功了 → 轻提示。
5. 页面上没有内容可显示 → 空状态。

## 6.2 轻提示

- 位置在右下角，宽 360px；640px 以下变成底部通栏。最多同时 3 条。
- 只用来确认已经完成的操作。可以带一个按钮：「撤销」或「打开」。
- 要用户改正的错误不用轻提示。保存失败是例外：用轻提示写原因，同时改动全部保留在页面上。
- 读屏会播报（`role="status"`），不抢焦点。

## 6.3 确认弹窗和消息框

确认弹窗是消息框的一种。消息框按 SAP Fiori 的「Message Box」分五类：

| 类型 | 用在 | 标题写法 | 按钮 |
|---|---|---|---|
| 确认 | 不可撤销或会影响别人的操作之前 | 问句，带动作和对象：「撤回审批？」 | 取消、动作名 |
| 删除 | 删除之前 | 一个：「删除 <对象> <编号>？」；多个：「删除选中的 n 个<对象>？」 | 取消、删除（红字） |
| 错误 | 和字段无关、页面上放不下的错误，例如提交时服务器拒绝 | 写发生了什么：「没能提交审批」 | 关闭 |
| 警示 | 可以继续、但后果要用户知道 | 问句：「折扣低于 8 折，仍然提交？」 | 取消、动作名 |
| 信息 | 用户必须读到、又不需要决定的说明 | 陈述句 | 关闭 |

- 只在操作不可撤销、或者会影响别人时弹：删除、作废、撤回审批、退回、批量修改。能撤销的操作直接执行，用轻提示加「撤销」。
- 成功不用消息框，用轻提示。
- 正文一句话说后果：「删除后不能恢复。」需要时再加一句怎么办。
- 按钮最多两个：左边「取消」，右边写动作本身（删除、作废、撤回）。危险操作的按钮是红字，其他是主按钮。不写「确定」「是」「否」。
- 例外：离开有草稿的单据时，弹窗有四个按钮（[5-单据.md](5-单据.md) 5.7），用 `openConfirm()` 的 `choices`。
- 打开时焦点在「取消」上，需要填原因时焦点在原因框里。
- 需要原因的（退回、作废），原因是必填的多行文本框，空着点按钮时在框下方写「作废原因没填」。
- 一次只开一个模态弹窗。新建弹窗里有未保存内容时关闭，就在弹窗底部原地问「继续编辑 / 放弃 / 创建」，不叠第二个弹窗。

## 6.4 批量处理的结果

规则来自 Fiori 的「Processing Multiple Items」。参考实现：`showBatchResult()`。

- 全部成功：轻提示「已删除 5 个客户」，不弹窗。
- 部分或全部失败：弹窗。标题写「删除了部分客户」或「没有客户被删除」；第一行写「3 / 5 个已删除」；下面逐条列出没处理的对象和原因。按钮只有「关闭」。
- 处理完以后，成功的从勾选里去掉，失败的保持勾选，用户改正后可以直接再试一次。
- 事先就知道有几条不能处理时（例如勾选里有已生效的报价单），执行前先问：「选中的 5 个报价单里有 2 个已生效，不能删除。删除其余 3 个？」，按钮「取消」「删除 3 个」。
- 处理时间超过 1 秒时显示进度「正在删除 3 / 5」，可以停止。停止后已处理的不回退，结果按上面的规则显示。

## 6.5 弹窗尺寸

| 类 | 宽度 | 用在 |
|---|---|---|
| `.wb-dialog` | 400px | 确认弹窗、一两个字段 |
| `.wb-dialog.is-form` | 560px | 一组字段的短表单：添加明细行、批量编辑、批量结果 |
| `.wb-dialog.is-wide` | 880px | 选择弹窗（表格）、值帮助弹窗、宽表单 |
| `.wb-create` | 640px | 新建弹窗 |

弹窗高度跟随内容，超过窗口高度时弹窗内滚动，标题和按钮不动。

## 6.6 文案写法

- 写发生了什么、怎么办，两件事各一句。「还有 1 项必填没填：客户联系人。补齐后再提交。」
- 写具体的对象和数字：「已删除 3 条」，不写「操作成功」。
- 不写「请」「您」「抱歉」，不写感叹号。
- 错误说明写改法：「填 0～999 的整数」「要晚于报价日期」。
- 字段名和界面上的标签一字不差。
- 日期、数字、金额按 [10-数据格式.md](10-数据格式.md) 写。

## 6.7 空状态

规则来自 Fiori 的「Empty States」。

- 有标题和说明两部分。标题写为什么空：「没有符合条件的客户」「还没有报价单」。说明写下一步能做什么，最多 3 行。
- 操作只用普通按钮或链接，不用主按钮：清除筛选、新建、返回列表。没有可用的出口时只写原因。
- 一屏只出现一个空状态。列表空了时，侧面板和汇总不再各放一个。
- 筛选后没有结果时，标题后写出当前条件：「没有符合条件的客户：阶段是已成交、负责人是周航」。
- 没有权限时写明缺什么权限、找谁开通。
- 不用插画。

## 6.8 忙碌和占位加载

规则来自 Fiori 的「Busy State」。

| 情况 | 写法 |
|---|---|
| 1 秒内完成 | 不显示任何加载状态 |
| 按钮触发、超过 1 秒 | 按钮显示忙碌（`aria-busy="true"`）并禁用，页面其他部分照常可用 |
| 页面或区块首次加载 | 在内容的位置显示同尺寸的灰块（`.wb-skeleton`），一行文字一块，表格按行画 |
| 已有内容在刷新 | 保留旧内容，只在区块标题旁写「正在更新」，不换成灰块 |
| 超过 10 秒 | 写明还在处理，能停止的给「停止」 |

- 只标正在加载的那部分。侧栏、页眉、导航照常可用，不用整页遮罩和转圈。
- 灰块用 `--wb-fill`，以 2 秒为周期整体变淡再恢复。系统开启「减少动态效果」时不动。
- 加载失败时在内容的位置写原因和「重试」。页面上其他能用的部分照常可用。
