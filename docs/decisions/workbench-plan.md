# Aham UI 7.1 工作台规划与迁移

## 决策

以用户确认的 C 风格高密度 CRM 单据作为新模式的起点。Circle / Linear 提供全宽工作空间、紧凑标题、内容与属性栏分工的参考；Aham 继续决定颜色、字体、组件外观、状态和跨介质规则。项目参考：[Circle](https://github.com/ln-dev7/circle)。本次没有导入 Circle 代码或依赖。

不把 UI 规范等同完整应用框架。规范覆盖视觉、布局、组件意图、行为和验收；业务数据、权限、审批与部署仍归产品工程。

## 本次落地（7.1）

1. **规范层**：网页增加 content / workbench 子模式；独立 WORKBENCH 正式章节，覆盖单据、密度、摘要、状态、响应式和键盘。
2. **Token 层**：新增 workbench 命名空间，以引用继承原有字体、颜色和密度；为工作台壳增加结构尺寸，不覆盖全局值。
3. **契约层**：在 17 个基础组件上增加 4 个组合模式；修复 table compact=28 与 Token=32 的冲突，明确按钮 loading / focus / icon-only 行为。
4. **参考层**：把批准的报价原型整理为独立 HTML / CSS / JS 示例，采用 12px 正文、240px 摘要与规范断点。真实计算、筛选、输入校验、本机保存、主题与密度；审批明确模拟。
5. **工具层**：可重复生成工作台变量与断点；恢复组件 CSS 提取并隔离预览布局，补充测试和 CI。
6. **消费层**：修正机器读取顺序为 tokens → 正式规则 → 契约 → 实现 → 示例；css.json 明确降为兼容镜像。

## 迁移矩阵

| 现状 | 本次迁移方式 | 兼容边界 |
|---|---|---|
| 普通 `.track-web` 内容页 | 保持原布局 | 不全局改为全宽 |
| 新 CRM 单据 | 显式使用 `.aham-workbench` 和 workbench.css | 不与旧全局组件类混写 |
| 现有密集表格 | 行高采用 tokens 的 32px compact | standard 36px 不变；48px 是双行模式 |
| 旧 css.json 消费者 | 读取改为 tokens.json；暂留镜像 | 镜像未覆盖新增工作台值 |
| components.css 使用者 | 重新生成并检查按钮 / dialog | 页面脚手架不再来自聚合文件；宿主自己提供布局 |
| `.design_library/Aham` 等下游导出 | 后续由消费端重新导入 canonical design-system | 本地镜像及用户未提交文件不在本次覆盖范围 |
| macOS / Office / 邮件 | 保持原轨道规则 | 不套网页密度和右栏模板 |

安装/使用：仓库根运行 `python3 -m http.server 8765 --bind 127.0.0.1`；访问 `http://127.0.0.1:8765/design-system/examples/crm-quotation.html`。示例仅保存虚构资料，不应作为存储真实业务数据的方案。

## 后续产品接入顺序

| 顺序 | 范围 | 出口条件 |
|---|---|---|
| 1 | 在 CRM 分支迁移一个真实报价页 | 用户确认视觉；服务端金额与界面一致；保存/审批/失败真实闭环 |
| 2 | 客户列表、商机详情、合同单据复用 | 统一导航、过滤和属性栏；避免每页自造密度 |
| 3 | React / 其他前端的正式组件适配 | 保留契约；受控输入、焦点、错误、加载与权限完整 |
| 4 | 旧预览与历史 CSS 统一生成 | 清完硬编码和重复别名；亮暗、键盘、视觉回归覆盖后才宣布全面合规 |

这些是后续实施规划，不包含本次更改生产 CRM、上线部署或对所有老页面做已通过验收的声明。

## 发布与回退

这是新增模式的 minor 版本 7.1.0，通过独立分支 / PR 审阅后合并。工作台按页面选择启用，可移除 CSS 引用回到原模式；合并前看 diff 和 CI。组件 CSS 去掉预览脚手架属于明确的修复，依赖这些非组件布局的页面需要补回自身布局。涉及生产系统时另行备份和验证，不由设计规范发布触发部署。
