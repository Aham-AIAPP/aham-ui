# 4 页面

本章落实设计理念的原则 1、2、4、5、6、7、10、16。

## 4.1 外框

示例：[examples/shell.html](../examples/shell.html)。

| 区域 | 尺寸 | 内容 |
|---|---|---|
| 侧栏 `.wb-rail` | 展开 220px，收起 52px | 顶部是产品名和工作空间；中间是导航项，可以分组；底部是设置和账户按钮，账户按钮打开账户菜单（[11-交互.md](11-交互.md) 11.6）。导航项 28px 高，图标 16px 加清楚的名称。⌘/Ctrl + B 展开或收起，选择记在本机，默认展开。收起时鼠标停留约 0.15 秒，整个导航（含当前模块的子页）浮在页面上展开，不推动页面，鼠标移开收回 |
| 页眉 `.wb-header` | 每条 44px，最多两条 | 第 1 条：导航开关（只在侧栏收起时显示）、面包屑或页面名称、视图页签、右侧的全局操作。第 2 条只在列表页出现：条数、筛选、显示选项 |
| 内容区 `.wb-main` | 剩余宽度 | 白底，直角，上、右、下铺到窗口边缘。和侧栏之间一条 1px `--wb-edge` 竖线。侧栏第一行和页眉第一行等高，在同一条水平线上 |
| 侧面板 `.wb-panel` | 属性栏 288px，预览 400px | 属性、预览、汇总。一次只开一个 |

- 页眉和侧栏固定，只有内容区滚动。单据页的单据头和锚点栏在内容区里吸顶，见 [5-单据.md](5-单据.md) 5.1。
- 导航名称准确、简洁，最多 6 个字，例如：首页、待办、客户、商机、报价、合同、场景、设置。汉字算 1 个字，英文字母和数字两个算 1 个字。展开的侧栏 220px，去掉内边距、图标和右侧计数，导航文字能用约 140px，14px 汉字放得下 10 个；限 6 个字是给字重 500 的当前项和右侧计数留出余量，名称不被截断。
- 侧栏用 `--wb-canvas` 底色，比内容区深一档。导航项的文字和图标用 `--wb-ink`，悬停用 `--wb-nav-hover` 底色，当前项和按下用 `--wb-nav-selected` 底色和字重 500。当前项不用主色。
- 侧栏的分组名用 12px、`--wb-muted`，例如「工作」「管理」。分组之间留 16px。
- 导航项右侧可以放计数，用 12px、`--wb-ink-2`、等宽数字。计数只给需要当前用户处理的数量，例如待办。计数和对应页面的列表读同一份数据，处理掉一条，两处同时减一；计数为 0 时不显示。
- 收起成 52px 时只显示图标，悬停显示名称和快捷键。
- 1024px 及以下，宽面板浮在内容上方，打开时取得焦点，Esc 关闭。
- 1024px 及以下，侧栏默认收起，展开时变成浮层。
- 640px 及以下，侧栏变成浮层，行高换成 44px，表单变成单列。
- Esc 每次只关最上面一层：弹层 → 浮动面板 → 导航浮层 → 搜索。关闭后焦点回到打开它的位置。

## 4.2 页型

按用户要做的事选页型。下表参考 SAP Fiori 的页型（floorplan）。

| 用户要做的事 | 页型 | 示例 |
|---|---|---|
| 在大量记录或单据里查找、筛选、批量处理 | 列表页 | [list.html](../examples/list.html) |
| 查看或修改一张单据：有明细、金额、审批 | 单据页 | [document.html](../examples/document.html) |
| 查看一条没有审批流程的记录：客户、联系人 | 记录详情页 | [record.html](../examples/record.html) |
| 新建简单的记录：必填字段少于 8 个、没有明细表 | 新建弹窗，标题写「新建客户」这类对象名，第一个字段是对象的名称（`nameLabel`），提交前查重（`check`） | `openCreateDialog()` |
| 新建单据：有明细表或必填字段 8 个以上 | 单据页的新建态（[5-单据.md](5-单据.md) 5.5） | — |
| 改个人或工作区的设置 | 设置页 | [settings.html](../examples/settings.html) |
| 打印单据 | 打印预览页 | [print.html](../examples/print.html) |
| 逐条处理分给自己的待办：待审批、待确认 | 工作清单 | [worklist.html](../examples/worklist.html) |
| 登录后先看今天要关心的事：等我处理、我在等别人、已逾期 | 我的工作台 | [home.html](../examples/home.html) |
| 客户和我方共用、按阶段推进的对象：场景、需求、工单 | 共用对象的列表页和详情页（4.15） | [scenes.html](../examples/scenes.html)、[scene.html](../examples/scene.html) |
| 配置成员能看什么、能改什么、能做什么 | 设置页的成员与角色（4.14） | [members.html](../examples/members.html) |
| 新建过程分 3–8 步，用户不常做、前后步骤有依赖 | 向导 | 没有参考实现 |
| 先输入一个编号或名称，再打开对应的单据 | 初始页 | 没有参考实现 |
| 请公司外部的人填写信息：客户提交需求、供应商补资料 | 对外填报页（4.12） | [form.html](../examples/form.html) |

同一个产品里，三种版式按页型组合：我的工作台、列表页和工作清单用标准密度（2.7）；对外填报页用舒展的单栏；需要边读边改的记录详情页用正文加属性栏的分栏。

**工作清单**（Fiori 的 Worklist）

- 处理的是已经分给当前用户的事项，数量通常在一屏到几屏之间。
- 没有筛选行。用分段按钮分几类：「待我审批 12」「我已处理」，每类写条数。数量多时可以有搜索。
- 每行末尾放处理按钮，最多两个，用文字：通过、退回。需要原因的操作（退回）弹窗填原因。
- 处理完的行从「待我审批」移到「我已处理」，轻提示带「撤销」。
- 可以勾选多行批量处理，结果按 [6-反馈.md](6-反馈.md) 6.4 显示。
- 点行的名称打开单据页，在单据页里处理也一样。

**我的工作台**

- 登录后的第一页，跨对象列出当前用户要关心的事。导航项写「首页」。
- 顶部一行概况数字（4.13）：等我处理、我在等别人、已逾期。点数字跳到下方对应的分组。
- 下方是单行列表，按这三类分组。每行写对象类型、编号、名称、在等谁做什么、计划日期。逾期的日期用 `.wb-next-date.is-overdue`。
- 行内不放处理按钮，点名称打开对象页处理。审批类的批量处理在工作清单里做。
- 不放图表、公告和快捷入口卡片。

**共用对象**（场景、需求、工单）

- 列表页按阶段分组，每行写在等谁（[6-反馈.md](6-反馈.md) 6.9），AI 判断待确认的行带 AI 标记。视图分「全部」「等我处理」「AI 待确认」。
- 详情页用记录详情页的分栏，主内容从上到下：标题 → 摘要行 → 下一步提示条 → 阶段条 → 现在和希望 → AI 判断（[8-AI协作.md](8-AI协作.md) 8.7）→ 问题和回答，附件跟着它回答的问题 → 内部备注（仅我方）→ 动态和评论框。
- 客户方能看什么按 4.15 处理。

**向导**（Fiori 的 Wizard）

- 3–8 步。少于 3 步用单据页的新建态，多于 8 步拆成几个单据。
- 顶部是步骤条，写每一步的名称；已完成的步骤可以点回去改。
- 一页只显示当前这一步。底部是「上一步」「下一步」；最后一步是汇总页，列出全部填写内容，每段带「编辑」，按钮是「提交」。
- 离开向导时，按单据的草稿规则处理（[5-单据.md](5-单据.md) 5.7）。

**初始页**（Fiori 的 Initial Page）

- 页面中间只有一个输入框（带值帮助，[3-控件.md](3-控件.md) 3.7）和「打开」按钮。
- 输入框下方列出最近打开的 5 条。
- 适合用户手里已经有编号的场景，例如扫码录入、按单号查单。

## 4.3 列表页

结构从上到下：页眉第 1 条（页面名称、视图页签、搜索）→ 页眉第 2 条（条数、导出、筛选、显示、面板开关）→ 筛选行（有条件时才出现）→ 列表 → 翻页区。右侧可以开 400px 预览面板。

**行和列**

列表页用单行列表（`.wb-table.wb-list-rows`），做法参考 Linear：一行一个对象，不显示表头，按分组排列。

- 仍用 HTML 表格，表头保留给读屏软件，视觉上隐藏。排序和显示哪些列放在「显示」选项里（4.6）。
- 数据行 44px（`--wb-list-row`），显示选项里切到紧凑时 36px。只放一行字，不折行。分组行 36px，底色 `--wb-fill`，底边一条 1px `--wb-line`。分组全部收起时，每组之间仍有一条线隔开。吸顶的单元格不显示表格边框，所以分组行的线用 `inset` 阴影画，写分组名和条数；按阶段分组时，分组名前放阶段图标（[3-控件.md](3-控件.md) 3.15）。
- 一行从左到右：勾选框（悬停或已有勾选时才显示）→ 编号（12px、`--wb-muted`、等宽数字、固定宽度）→ 阶段图标或状态 → 名称（正文色，占满剩余宽度）→ 标签 → 数字 → 日期（12px、`--wb-muted`）→ 人员头像（20px，不写姓名）。
- 名称左对齐，从名称往右的各项靠右排列。同一个列表里同一项的右边缘对齐（原则 6）。
- 640px 及以下，判断一行只需要名称、在等谁和负责人的列表改成两行排列（`data-mobile="stack"`）：第 1 行写名称和标签（`.wb-cell-name`），第 2 行写在等谁（`.wb-cell-wait`），头像（`.wb-cell-end`）靠右跨两行，编号、日期和其他列隐藏，勾选框也隐藏。
- 要靠数字或多列判断的列表不用两行排列，在滚动区里横向滚动。表格的最小宽度设为各固定列之和加 240px，名称列至少留 240px，不被挤没。
- 数字右对齐、等宽数字。单行列表里没有值的项留空，不写「–」，做法参考 Linear：一行是一个对象，缺的属性不占视线。带表头的数据表格仍按 [10-数据格式.md](10-数据格式.md) 10.5 写「–」。数字默认 12px、`--wb-muted`；这一页要据此做判断的数字（例如待审批的金额）用 14px 正文色，一个列表最多一列。
- 行之间画 1px `--wb-line-soft` 横线，不画竖线。
- 状态用阶段图标或状态圆点加文字，不给整行上色。勾选的行用 `--wb-selected` 灰底。
- 已作废、已停用的记录可以整行文字变浅（`<tr data-dimmed>`），状态照常写；行里的按钮和链接保持正文色，仍然可以操作。
- 状态和负责人这类单元格可以直接改：单元格是按钮，点开选择菜单，选中即保存，用轻提示确认并提供「撤销」。同样的修改也能从右键菜单、命令面板和快捷键 S / A 进入（`openPicker()`）。阶段或状态由数据算出、不能手改的对象不设 S，行里的阶段图标只显示，不是按钮。

需要逐列比较数字的场景，例如报价明细、库存、对账，仍用带表头的数据表格（`.wb-table`）：默认行高 36px，显示选项里可以切到 32px；表头不加底色，用字重 500 和次要文字色区分，在滚动区里吸顶（表格和滚动区之间不能再有设了 `overflow` 的容器，否则表头按那个容器吸顶、看起来不动）；列标题可以点击排序，当前排序列加 `aria-sort`。

**页眉第 2 条**

从左到右依次是「导出」「筛选」「显示」「面板开关」，都是 28px 小号按钮。文字按钮连成一组，只用图标的面板开关放在最右端。显示选项和默认不同时，「显示」右上角加 6px 圆点。

**勾选和批量操作**

- 勾选后页眉第 2 条换成批量条：已选条数、清除选择、批量操作。高度不变，不遮挡列表。
- 批量条最多 3 个按钮，按 [3-控件.md](3-控件.md) 3.4 排。示例页是批量编辑、导出、删除。
- 本页全选且结果多于一页时，提供「选择全部 N 条」。筛选、搜索或视图变了，清空勾选。
- 批量删除这类不可撤销的操作先弹确认弹窗（[6-反馈.md](6-反馈.md) 6.3），标题写「删除选中的 n 个客户？」。
- 有失败的，按 [6-反馈.md](6-反馈.md) 6.4 弹结果，失败的保持勾选。

**批量编辑**（Fiori 的 Mass Edit）

- 勾选 2 条以上后点「批量编辑」，弹窗里每个可以批量改的字段一个下拉。
- 下拉的前两项固定：「保留原值」「留空」。必填字段没有「留空」。
- 勾选的记录这个字段值都一样时，预选这个值；不一样时预选「保留原值」。
- 点「保存」后按批量处理的结果规则提示。全部成功时轻提示「已修改 5 个客户」。
- 不能批量改的字段（编码、名称、金额）不出现在弹窗里。

**行内展开**

- 列表按几十条设计。收起的行只放判断用的 4–5 项。
- 行可以展开看明细时，同一个列表同时只展开一行：展开新行时，上一行自动收起。写法是 `.wb-expand` 里每行一个 `<details>`，同一列表的行用同一个 `name`；`initSingleExpand()` 给不支持 `name` 的浏览器补上同样的行为。
- 嵌在详情页里的列表：多于 1 条时给筛选，多于 8 条时给搜索。
- 表格没有数据时不显示表头，只显示空状态（[6-反馈.md](6-反馈.md) 6.7）。

**空结果和翻页**

- 没有结果时写明当前条件，并给出能用的出口：清除筛选、清除搜索、查看全部。
- 条数写在页眉第 2 条左侧。翻页区只放当前范围、每页条数、上一页和下一页。
- 筛选、搜索或视图变了，回到第 1 页。

## 4.4 筛选

按 Fiori 的「Filter Bar」改写，并保留 Linear 式的条件标签。

- 条件改了立即生效，不需要「查询」按钮。只有单次查询超过 2 秒的数据源才加「查询」按钮，条件改了先不查，按钮变成主按钮。
- 搜索框是第一个筛选条件，放在页眉第 1 条。
- 必须有条件才能查的字段（例如公司代码、会计期间）是必填筛选：进入页面时预置默认值，条件标签不能移除，只能改值。
- 筛选行收起时，页眉第 2 条写摘要：「3 个筛选生效：阶段、负责人、行业」，最多列 5 个字段名，更多的写「等 7 个」。筛选行收起和摘要没有参考实现。
- 列表有编辑状态时（[5-单据.md](5-单据.md) 5.7），筛选里有「编辑状态」：全部、我的草稿、他人正在编辑。

- 点「筛选」打开选择菜单：先选字段，同一个弹层里再选值，不叠第二个弹层。
- 在字段列表里直接输入选项值，会列出「字段 › 值」和条数，选中即生效。
- 条件生效后，页眉下方出现筛选行：添加筛选、条件标签（`.wb-chip`）、清除。没有条件时整行不出现。
- 条件标签分四段：字段、条件、值、移除。条件和值都能点开修改。
- 条件类型：文本（包含、不包含）；选项（是、不是、是其中之一、不是其中任何一个）；数字（不少于、不多于、介于）；日期（晚于、早于、介于）。
- 每个字段最多一条条件。条件、视图、搜索词、页码写进网址，可以分享；网址里无法识别的条件丢弃，并提示丢弃了几条。
- 参考实现：`initFilter()`，筛选语义以 `FILTER_OPERATORS` 和 `matchesFilter()` 为准，服务端查询按同样的语义实现。

## 4.5 视图

视图保存一组筛选、排序、分组和显示哪些列，按 Fiori 的「Variant Management」改写。

- 视图写在页眉第 1 条的视图页签里（`.wb-seg.sm`），和面包屑之间留 12px。页签没有外框；其他视图用 `--wb-ink-2` 文字，悬停时加 `--wb-hover` 底色；当前视图用 `--wb-selected` 底色、正文色和字重 500，不画描边，和侧栏当前项的写法一致。系统自带的叫标准视图（示例页的「全部客户」「我负责的」「本周新增」），不能改和删。
- 在当前视图上改了筛选、排序、分组或列，视图名后加「*」，旁边出现「另存视图」。
- 「另存视图」打开弹窗：名称（必填，最多 20 个字）、可见范围（只有自己 / 工作区所有人）、是否设为默认。
- 一个人只有一个默认视图，进入列表时打开它。没有设过时，默认是第一个标准视图。
- 公开视图只有创建人能改；其他人可以另存一份自己的。
- 视图多于 5 个时，分段按钮换成下拉，下拉底部是「管理视图」。
- 显示选项里的行高和每页条数属于个人设置，不随视图保存。

## 4.6 显示选项

- 弹层宽 320px：分组、排序、行高（标准 / 紧凑）、显示哪些列、恢复默认。
- 修改立即生效，记在本机，不写进网址。读取时逐项校验，未知列丢弃，新增列按默认补齐。
- 参考实现：`initDisplay()`。

## 4.7 列表键盘和预览

- 列表里只有当前行在 Tab 顺序中。↑↓ 移动，Home / End 到首尾，空格打开或关闭预览，Enter 打开详情，X 勾选，Shift + ↑↓ 扩展勾选。
- 预览面板可选。行里已经写出在等谁、预览只会重复详情页开头的列表，不设预览；这时空格不拦截，照常滚动页面（`initListKeys()` 不传 `onPreview`）。
- 焦点在行内的勾选框、链接或输入框上时，这些键交给控件本身。输入法组字时不响应。
- 键盘焦点行：浅灰底加 1px 蓝色上下边线。
- 预览面板 400px 宽，只放快速判断需要的信息：名称、状态、关键属性。焦点留在列表里。
- 参考实现：`initListKeys()`、`initPanels()`。

## 4.8 记录详情页

- 页眉一条：面包屑（最后一段是记录编号）、「当前位置 / 总数」、上一条和下一条（快捷键 J / K）。
- 面包屑和返回按来路：从哪一页进来，就回到哪一页。例如从项目里点开的记录，返回回到项目，不回到记录列表。示例页把来路存在 `sessionStorage` 里（examples/record.mjs）。
- J / K 翻到同一列表的上一条或下一条时，面包屑只换最后一段，来路保留。翻页替换当前历史记录，不新增一条：浏览器后退和返回按钮都回到来路页，不逐条退回翻过的记录。上一条、下一条取打开详情时那个列表的顺序，按当时的筛选和分组。
- 正文和属性栏始终是两栏，宽屏不加栏。两栏一起最宽 `--wb-record-width`：窗口每宽 4px，内容区宽 1px，最宽 1840px；再宽时两侧留白、整体居中，页眉的左右边缘跟着内容区，按钮不贴到窗口最右。
- 主内容区左右边距和单据页相同（`--wb-page-gutter`），标题、提示条、关联记录和评论框都左对齐、铺满这一栏。成段文字一行最宽 672px（`--wb-body-width`），14px 下正好 48 个汉字（W3C《中文排版需求》横排一行的上限）。右侧 288px 属性栏（`--wb-panel-props`）单独滚动，和正文之间画一条分隔线。1024px 及以下属性栏移到正文下方。
- 标题和摘要行（`.wb-detail-head`）滚动时停在页面上方，不跟着滚走；滚过 24px 后收成一行（`.is-stuck`：标题缩小、摘要行一行省略），640px 及以下只留标题。属性栏单独滚动，正文滚到哪里，金额、负责人这些属性都还在眼前。
- 主内容从上到下：标题（20px）→ 摘要行（状态、编号、负责人）→ 还缺什么（有缺的信息时，[3-控件.md](3-控件.md) 3.19）→ 要点（`.wb-record-summary`，这个对象自己的事，例如需求概要、主营业务、活动目标；要点列表按 320px 一栏铺满正文宽度，放得下几栏排几栏）→ 关键信息（3.16，最后一格是下一步；下一步已在关键信息里时不再放下一步提示条）→ 阶段条（有阶段时，3.12；要看每条记录落在哪一段时用带事件的阶段条，3.17）→ 工作记录（有往来记录时，3.18）→ 关联记录 → 备注 → 动态。
- 正文只写对象本身。判断推进要用的 3–4 个数字，例如金额、计划日期、停留天数，放在标题下的关键信息里，不放在属性栏或页面右上角；写法见 [3-控件.md](3-控件.md) 3.16，可以带「已逾期」这类状态。其余完成度、统计和属性放右侧属性栏。参考实现见 [examples/parts-record.html](../examples/parts-record.html)。
- 同一件事一屏只出现一次（原则 7）：阶段只出现在关键信息和阶段条里，标题旁、摘要行和属性栏不再写；属性栏里有的字段，要点里不再放成标签。
- 颜色只表达含义（原则 8）：蓝是当前状态和主操作，琥珀是缺了要补的信息（未填的金额、没安排的下一步、缺的销售策略），红是风险和逾期，绿是已完成。区块之间靠 32px 间距分开，只有关键信息画外框，要点不铺底色。
- 同一个对象日常推进的内容一页到底，不用页签切分。内容随阶段出现，没到的阶段不显示空的区块。和日常推进不同的另一种工作，例如策略分析、资料管理，可以另开页签，页签名写这项工作，一个对象最多三个页签。
- 工作记录：跟进、电话、拜访、处理记录这类对象本身的往来，是正文的一部分，放在正文之后、关联记录之前，最新的在上；还没完成的任务排在最上面，带处理按钮。它和页尾折叠的动态分开，动态只放系统记下的修改和事件。写法见 [3-控件.md](3-控件.md) 3.18。
- 问题类记录（场景、需求、缺陷、工单）的正文先写要解决的问题，用「现在」「希望」两栏对照（`.wb-problem`），再写其他内容。640px 及以下两栏上下排列。
- 一个对象只有一套阶段。客户用客户状态（潜在、跟进中、已成交、已流失），销售阶段放在商机上，客户列表按客户状态分组。客户页的下一步提示条从进行中的商机取：「推进商机 OPP-0187：提交方案初稿」。
- 属性栏每行是「标签 + 值」，行高 32px，标签 14px（和值同号、同一基线）、`--wb-muted`、88px 宽，不省略。分组名 12px、`--wb-muted`，分组之间留 24px。可改的值是按钮，点开选择菜单，选中即保存，用轻提示确认并提供「撤销」。
- 动态、修改记录和版本记录默认折叠在页尾一行（`.wb-fold`）。折叠行写名称、条数、创建人和最近日期，例如「动态 8 条 · 林悦创建 · 最近 10-16」。
- 展开后动态按时间正序，最新的在底部。评论框不随动态折叠，始终显示在页尾。评论框 ⌘/Ctrl + Enter 发送，单按 Enter 换行。
- 有明细和金额的单据不用详情页，用单据页。
- 参考实现：`initPropertyPickers()`、`initComposer()`。

## 4.9 设置页

- 设置页只放工作区配置：成员与角色、字段与标签、审批流程、编号规则、集成。这些配置影响所有人，需要链接和保存按钮。个人偏好放在账户菜单打开的分栏弹窗里，见 [11-交互.md](11-交互.md) 11.6。
- 左侧 220px 设置导航，右侧内容最宽 640px。1024px 及以下设置导航移到顶部。
- 设置内容按分区排列，分区之间 32px。分区里每一行左边是标题和说明，右边是控件，行之间用 `--wb-line-soft` 横线分隔，行最小高 64px。说明用 12px。右侧的输入框和下拉框同宽 200px（`--wb-setting-control`），右边缘对齐。
- 页眉只写面包屑。影响范围写在页面第一段说明里，不在页眉重复。
- 工作区设置改了不立即生效。有改动时底部出现保存栏，写「有 n 项修改未保存」和「放弃修改」「保存」两个按钮，⌘/Ctrl + S 也能保存。离开页面前有未保存的改动时先问。
- 偏好弹窗里的单项设置改了立即生效，用轻提示确认；保存失败时恢复原值并说明原因。
- 恢复默认、删除工作区这类操作放在最后一个分区，按钮用红色文字，点击后弹确认弹窗。

## 4.10 表格选型和导出

**表格选型**（Fiori 的「Table Overview」）

| 数据 | 表格 | 参考实现 |
|---|---|---|
| 约 200 行以内，要在行里直接改 | 普通表格 `.wb-table`，分页或一次显示完 | 有 |
| 上千行，只看不改 | 普通表格加分页；或虚拟滚动，只渲染可见的行 | 分页有，虚拟滚动没有 |
| 多级分组、小计、合计 | 分组表格：分组标题行带小计 | 单级分组有，小计没有 |
| 有上下级关系：物料清单、组织 | 树形表格 `initTreeTable()` | 有 |

- 一个页面只放一种主表格。明细表和列表都遵守同一套行高、对齐和空值写法。
- 列多于 8 列时，默认只显示最常用的 6–8 列，其余放进显示选项。

**导出**（Fiori 的「Export to Spreadsheet」）

- 页眉第 2 条有「导出」，导出当前筛选和排序下的全部结果，不只是当前页。有勾选时，批量条里的「导出」只导出勾选的行。
- 导出的列、列的顺序、列名和屏幕上一致。金额导出为数字，不带千分位；日期导出为 YYYY-MM-DD。
- 文件名写对象和日期：「客户-2026-10-17.csv」。参考实现：`toCSV()`、`downloadText()`。
- 以 `=`、`+`、`-`、`@` 开头的单元格前加单引号，防止表格软件把它当公式执行。
- 超过约 100 万个单元格（行数 × 列数）时先提示，建议缩小筛选范围。导出超过 2 秒时显示进度，可以取消。

## 4.11 宽度和断点

| 断点 | 取值 | 变化 |
|---|---|---|
| `--wb-bp-wide` | 1600px 以上 | 单据页左右边距从 32px 加到 48px |
| `--wb-bp-context` | 1024px 及以下 | 侧面板浮在内容上方；详情页属性栏移到下方 |
| `--wb-bp-form` | 单据内容区 720px 及以下（容器查询） | 表单两列变一列，单据头的按钮移到标题下方 |
| `--wb-bp-log-split` | 工作记录区 960px 以上（容器查询） | 工作记录分两栏：左边内容，右边下一步和同时完成的任务 |
| `--wb-bp-mobile` | 640px 及以下 | 导航变浮层，行高 44px，轻提示变底部通栏 |

单据表单最宽 960px（`--wb-form-max`），更宽的屏幕上表单不再拉伸，明细表可以铺满。

## 4.12 对外填报页

示例：[examples/form.html](../examples/form.html)。

- 用在公司外部的人通过链接填写信息，例如客户提交需求、供应商补资料。外部的人不登录系统，也不认识系统里的模块。
- 版式是单栏居中，最宽 720px（`--wb-detail-width`），写法是 `.aham-workbench.wb-bare` 里放 `.wb-form-page`。
- 页面不显示侧栏、面包屑、目录和系统内部的名称。
- 页头一行写发起方的公司名和页面用途（`.wb-form-page-brand`），例如「华岳智造 · 设备需求填报」；下面是页面标题。页面里的「我们」指发起方。
- 链接发给已知的人时，带入已知的信息（企业名称、联系人、手机号），填写人只核对，不重填。
- 提交后显示编号、下一步提示条（等谁、做什么、计划日期）和查看进度的链接。
- 分步填写时，顶部只放分段进度（`.wb-form-progress`）和「第 n 步，共 n 步」，不列每一步的名称。
- 页脚左侧「上一步」，右侧「下一步」；最后一步右侧是「提交」，用主按钮。
- 外部的人只看到已经复核过的内容。未复核的 AI 判断和内部字段不显示。
- 不出现内部叫法。内部字段名对外换成通俗的说法，两个名称都登记在字段定义里。
- 手机宽度必须验收：390px 宽时控件高 44px，输入框字号 16px，页面没有横向滚动。

## 4.13 概况数字行

- 概况用一行数字（`.wb-nums`），每个数字是一个链接（`.wb-num`），点开对应的列表或筛选结果。
- 数字写在上，名称写在下：「12 / 场景」。数字用等宽数字（`.wb-tnum`）。
- 不做统计格、卡片和周报式的数字。数字行不加外框和底色。
- 数字为 0 时照常显示 0，链接打开的是空状态。

## 4.14 权限

示例：[examples/members.html](../examples/members.html)。

权限分三层，每个角色把三层都写清楚。

| 层 | 管什么 | 界面上的写法 |
|---|---|---|
| 数据范围 | 能看到哪些记录：本人负责、本组、全部 | 看不到的记录不出现在列表、搜索和计数里。从链接直接打开时显示无权限页（[6-反馈.md](6-反馈.md) 6.10） |
| 字段权限 | 能看哪些字段，能改哪些字段 | 不能看的字段不渲染，不显示星号或「已隐藏」。能看不能改的字段在编辑态显示成文字（[3-控件.md](3-控件.md) 3.3） |
| 操作权限 | 能做哪些操作：提交、审批、作废、导出、删除 | 永远做不了的操作隐藏。暂时做不了的操作禁用，旁边写条件（3.3） |

- 角色在设置的「成员与角色」里配置。成员表每行写姓名、邮箱、角色和数据范围；角色表每行写一个角色在三层上的权限。
- 改角色影响所有人，按设置页的保存栏保存（4.9）。
- 权限不足时写缺什么、找谁开通：「只有华东销售组能看这个客户，找许宁开通。」不写「权限不足」或错误代码。

## 4.15 多方共用的对象

示例：[examples/scene.html](../examples/scene.html)。页眉的「我方 / 客户方」切换只用于演示，产品按登录用户判断。

- 适用于客户方登录后和我方共用同一个对象，例如场景。只请外部人员填一次的，用对外填报页（4.12）。
- 人名后写所属组织的简称：「王卓 · 远川」「林悦 · 启衡」。
- 可见范围有两档：双方可见、仅我方。字段、分区、评论和附件各有可见范围，默认双方可见。
- 仅我方的内容在名称或标题后加固定标记 `.wb-scope`：锁图标加「仅我方」。双方可见的内容不加标记。
- 客户方看不到的内容由服务端过滤，页面不渲染。不用折叠、模糊或「已隐藏」占位。
- 评论框写明这条评论的可见范围，可以切换。切到仅我方时按钮带锁图标。
- 下一步提示条按看的人改写：等的人是当前用户时写「你」，是另一方时写人名加组织。
- AI 判断只有我方能确认。客户方只看到已确认的判断，规则见 [8-AI协作.md](8-AI协作.md) 8.7。
- 组件契约用 `visibility` 字段写明每个部分的可见范围。
